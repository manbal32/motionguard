## 현재 상태 (2026-09-18)

전체 영상에서 좌표를 추출하고 자동 4국면의 2D 관절각과 전후 변화를 확인하는 **연구용 시제품**입니다.
화면과 분석 흐름은 구현됐지만, 실제 각도 정확도·자동 국면 정확도·부상 위험 예측 성능은 아직 검증하지 않았습니다.

RULA·REBA 최종 점수와 action level은 아직 산출하지 않습니다. 몸통 기울기는 요추 회전각이 아니며,
현재 각속도는 관절각의 변화속도이지 클럽헤드 속도나 당기는 힘이 아닙니다.
‘엎어침’, ‘강하게 당김’, 특정 부상 위험을 현재 세 각도만으로 판정하지 않습니다.
RULA·REBA 적용표는 별도 논의 후 구현할 예정입니다.

### 현재 화면 구성

1. 작은 원본 영상과 자동 4국면 각도 표를 나란히 표시합니다.
2. 국면 선택 후 좌표가 겹쳐진 영상을 재생합니다. 옆 좌표 표는 기본 12개 관절을 표시하며, 전체 관절 보기에서는 추가 좌표를 확인할 수 있습니다.
3. 국면 전후 통계 아래에서 관절을 선택합니다. 세 그래프마다 관측 결과와 읽는 방법·확인할 사항을 옆에 배치합니다.
4. ‘확인할 구간’은 급변·측정 공백을 검토하는 표입니다. 현재 펼쳐서 표시하며 접기 전환은 아직 반영하지 않았습니다. 국면별 관절각 통계와 전체 좌표 기록은 접힌 영역에서 확인합니다.
5. 핵심 스틸컷에서는 얼굴의 점·연결선을 제외합니다. ‘국면 감지용 손목 Y’는 결측 보완·평활화한 세로 위치이며 각도가 아닙니다.

전체 프레임 좌표 표와 해당 CSV에서는 눈·귀·코·손가락을 제외합니다.
손목각 계산에 필요한 검지 등 원본 좌표는 내부 데이터와 전체 JSON에 보존합니다.
표시 변경은 Rerun으로 반영되며, 기존 분석 좌표를 다시 추출할 필요는 없습니다.

## 실제 Gemini 사용

`.env.example`을 `.env`로 복사하여 `GEMINI_API_KEY`와 계정에서 사용 가능한 `GEMINI_MODEL`을 입력하고 앱에서 Mock 모드를 끄세요.
공유 설정 예시의 모델은 `gemini-3.5-flash-lite`입니다. 2026-09-24 맥에서 짧은 직접 API 요청에 `OK.` 응답을 확인했습니다. 이는 연결 확인이며, 실제 영상 분석 결과 검증은 아직 완료하지 않았습니다.
`gemini-2.5-flash-lite`는 해당 계정의 테스트에서 신규 사용자에게 제공되지 않는다는 404 오류를 반환했습니다. 분석기 코드의 기본 모델은 여전히 `gemini-1.5-flash`이므로 `.env`의 `GEMINI_MODEL`을 반드시 설정하세요.
비용 관리를 위해 `.env.example`의 `MOTIONGUARD_MOCK_GEMINI=1`과 앱의 Mock 기본값은 유지합니다. 앱은 사이드바 Mock 토글 값을 명시적으로 사용하므로 실제 호출하려면 토글을 꺼야 합니다.
`.env`는 Git으로 동기화되지 않습니다. 회사 윈도우와 집 맥 각각에 키와 모델을 설정하고, 기존 앱이 실행 중이면 설정 변경 후 재시작하세요.
앱은 영상 이미지 대신 유효한 국면 각도 및 유효 프레임 좌표·각도 연구 데이터를 전송합니다. 아래 순차 테스트 스크립트는 4국면 관측값만 전송합니다.

## 측정 근거 및 코드 라벨 개선

- 단계별 피드백: 국면 / 항목 / 발견 / 근거 / 제안 표.
- 측정 불가 항목은 별도 측정 상태 표에 실제 실패 사유를 표시하며 분석 결과로 출력하지 않습니다.
- 유효 각도가 전혀 없으면 Gemini 호출 및 부상·질환 추론을 건너뜁니다.
- 각도가 일부만 있으면 해당 항목만 분석하고 나머지는 제외합니다.
- 질환 코드 사전은 ICD-10(NHS 5th edition)의 M77.0, M77.1, M54.5에 한정합니다. KCD 전체 사전이나 ICD-10-CM 청구 코드가 아닙니다.
- 모델이 명시한 질환 용어만 코드 후보로 정규화합니다. '팔꿈치 부담' 등 일반 표현을 구체적 질환으로 변환하지 않습니다.
- 원문과 불확실성·부정 표현을 보존하며, 코드가 붙어도 해당 피험자의 진단을 의미하지 않습니다. 근거·문맥은 검토 대상입니다.
- Mock은 측정값 표만 생성하며 질환을 지어내지 않습니다. 코드 사전 예시는 분석 결과와 구분해 표시합니다.

당시 검증: 단위 테스트 20개 및 합성 영상의 유효/전체 측정 불가 화면 흐름 통과. 실제 사용자 영상의 실패 원인은 새 측정 상태 표로 확인해야 합니다.


## 자동 4국면 분석 — 최신 사용법

1. 영상을 올리고 **분석 실행**을 누릅니다.
2. 전체 프레임 좌표 수집 후 어드레스/백스윙 탑/다운스윙/임팩트가 자동으로 표시됩니다.
3. 각 국면의 각도·산출 근거와 전후 0.25초의 각도 변화·관측 가동범위를 확인합니다.
4. 국면 선택이나 이전/다음 프레임은 결과를 확인하는 탐색 기능이며, 수동 기준점 지정은 필요하지 않습니다.

수동 국면 기준점 조정 기능은 제거했습니다. 기존 자동 이벤트 검출 방식은 유지하고, 신뢰도 때문에 이벤트 프레임을 옮기던 처리를 제거했습니다.
자동 이벤트 시점과 각도 관측값의 출처 프레임은 별도로 기록합니다.

### 각도 확보 순서

- 전체 신체 평균이 아닌 해당 각도를 구성하는 관절들의 최소 신뢰도로 계산 가능성을 판단합니다.
- 유효 좌표에서는 삼점 벡터로 직접 계산합니다.
- 최대 3개 결측 프레임이며 양끝 시간차가 0.12초 이하인 내부 공백에 한해 동일 관절의 좌표를 시간 비율로 선형 보간합니다.
- 영상의 처음/끝으로 외삽하거나 긴 결측 구간을 채우지 않습니다. 원본 좌표는 raw_series에 별도 보존합니다.
- 자동 감지 시점의 각도가 없으면 전후 0.15초 내 같은 국면 영역에서 가장 가까운 유효 관측값을 찾습니다.
- 좌표가 있지만 신뢰도가 낮으면 기하 계산값을 저신뢰로 표시하고 위험 평가·AI 추론에서 제외합니다.
- 좌표가 전혀 없거나 점들이 겹친 경우에는 유효 각도를 만들 수 없습니다. 주변 검색 이후에도 없는 값을 생성하지 않습니다.

출처: direct / coordinate_interpolation / nearby_frame_direct / nearby_frame_coordinate_interpolation / low_confidence_geometry 등.
보간은 영상 측정의 정답이 아니라 추정입니다. 빠른 동작에서는 오차가 커질 수 있으므로 출처와 원본을 함께 검토해야 합니다.

### 자동 전후 비교

같은 쪽 관절에 대해 국면 시점 전후 0.25초의 최소/최대/관측 가동범위/변화속도를 계산합니다.
기준 프레임이 누락되면 국면 내 인접 유효 프레임을 사용하고 기준 출처를 표시합니다.
좌우를 섞지 않습니다. 보간되지 않은 측정 공백을 건너 변화속도를 계산하지 않습니다.
관측 가동범위는 영상상 2D 움직임 범위이며 최대 신체 유연성·임상 ROM·부상 확률이 아닙니다.

전체 원본 및 보간 좌표, 관절별 신뢰도, 각도 출처, 자동 이벤트, 국면별 전후 분석을 JSON으로 저장할 수 있습니다.
실제 Gemini 모드에서 탐색은 재호출을 발생시키지 않으며 보고서 갱신 버튼으로 명시적으로 실행합니다.

당시 검증: 단위 테스트 33개 및 합성 영상의 자동 4국면/보간된 각도 표/전체 결측 표시/프레임 탐색 흐름 통과.
실제 사용자 스윙 영상에서의 각도 정확도는 아직 검증하지 않았습니다.

## Gemini API 순차 실연동 테스트 (2026-09-18)

프로젝트의 `samples/`에 `golf1.MP4`부터 `golf5.MP4`까지 넣고,
`.env.example`을 `.env`로 복사하여 `GEMINI_API_KEY`, `GEMINI_MODEL`을 설정합니다.
키는 출력하지 않습니다. 계정에서 사용 가능한 모델명을 명시해야 합니다.

프로젝트 폴더에서 실행:

```powershell
.\.venv\Scripts\python.exe scripts/test_gemini_api.py
```

- 모든 영상과 환경 설정을 먼저 검사한 뒤 1~5번을 순서대로 처리합니다.
- 전체 좌표 추출 → 기존 자동 4국면 감지 → 기존 각도 복구 → Gemini 호출 순서입니다.
- 전송 범위는 4국면의 유효 각도 및 보간/인접 프레임 등 출처입니다. 영상·전체 좌표 시계열은 전송하지 않습니다.
- 결과는 프로젝트 내 `outputs/gemini_results/golf{N}.json`에 입력 각도와 `result.raw_response`를 포함해 저장합니다.
- API가 JSON 형식으로 답하지 않은 경우 `real_gemini_unparsed`로 원문을 보존합니다.
- 유효 각도가 없으면 API를 호출하지 않고 `insufficient_data`로 저장합니다.
- `.env`의 Mock 설정과 관계없이 실제 API를 사용합니다. 오류를 Mock으로 대체하지 않습니다.
- SDK 재시도를 끄고 429/quota 오류 발생 시 즉시 중단합니다(종료 코드 2). 기타 오류도 중단합니다(종료 코드 1).
- 완료·측정 부족·남은 영상과 실패 단계는 콘솔 및 `outputs/gemini_results/progress.json`에서 확인합니다.
- 재개 예: `...python.exe scripts/test_gemini_api.py --start 3`. 지정 번호부터 5번까지 실행하며 같은 이름의 결과는 덮어씁니다. 진행 파일은 이번 실행 기준입니다.
- 호출 제한 시간은 120초, 기본 각도 신뢰도는 0.5입니다(`--confidence`로 변경).

스크립트의 순차 저장 및 quota 중단은 모의 API 테스트로 검증합니다. 실제 Gemini 호출 검증은 샘플 영상과 API 설정을 준비한 후 실행해야 합니다.
