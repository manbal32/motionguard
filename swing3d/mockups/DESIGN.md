# 디자인 방향

이 문서가 시각 기준이다. "세련되게" 같은 말로 판단하지 말고 여기 적힌 규칙으로 판단해라.

## 한 줄

**웹 앱이 아니라 계측 장비처럼 보이게 한다.**

골프 중계의 탄도 추적 그래픽, 생체역학 실험실의 계측 기록지가 참조점이다.
둥근 카드와 그림자로 블록을 띄우지 말고, 얇은 선과 정확한 정렬로 구조를 만든다.

## 핵심 규칙 — 색은 이상이 있는 곳에만

화면 전체는 거의 무채색이다. **벗어난 값이 있는 곳에서만 색이 나타난다.**

| 역할 | 처리 |
| --- | --- |
| 측정값 | 본 화이트. 색을 쓰지 않는다 |
| 교본 기준 | 점선 또는 얇은 눈금. 회색 |
| 벗어남 | **호박색 하나.** 기준과 차이가 임계 이상일 때만 |
| 과장 표시 | 같은 호박색을 더 진하게. 과장은 벗어남의 연장이다 |

이것은 장식이 아니라 정보 규칙이다. 색이 보이면 거기에 문제가 있다는 뜻이고,
색이 없으면 정상이라는 뜻이다. 이 약속을 깨지 마라.

청록·보라·초록을 데이터 색으로 쓰지 마라. 이전 시안의 색 약속은 폐기한다.

## 토큰

```css
:root{
  /* 바탕 — 따뜻한 근접 검정. 잔디의 녹색이 아주 약하게 섞여 있다 */
  --ground:    #0b0e0d;
  --ground-2:  #101413;   /* 표면이 한 단 올라갈 때만 */
  --rule:      #1e2523;   /* 기본 선 */
  --rule-hi:   #2d3634;   /* 강조 선 */

  /* 잉크 */
  --ink:       #e9e7e0;   /* 측정값·본문 */
  --ink-2:     #99a09b;   /* 보조 */
  --ink-3:     #5f6865;   /* 라벨·단위 */

  /* 유일한 색 */
  --signal:    #d98a2b;   /* 벗어남 */
  --signal-dim:#8a5a1c;   /* 벗어남 배경 */

  --sans: "IBM Plex Sans KR", system-ui, sans-serif;
  --mono: "IBM Plex Mono", ui-monospace, monospace;
}
```

## 타이포그래피

**IBM Plex Sans KR + IBM Plex Mono.** 한 가족이라 섞어도 어긋나지 않는다.
Inter 와 Space Grotesk 조합을 쓰지 마라. 그것이 AI 기본값이다.

- **모든 수치는 모노스페이스**다. 각도, 시간, 프레임 번호, 토큰 수 전부.
  `font-variant-numeric: tabular-nums` 를 함께 건다.
- **단위는 수치보다 한 단계 작고 흐리게.** `35.5` 는 크게, `°` 는 작게.
- **섹션 라벨은 작은 대문자**다. 11px, `letter-spacing: .14em`, 대문자화, `--ink-3`.
  한글 라벨은 대문자화가 없으므로 자간만 벌린다.
- 제목은 Plex Sans KR 600, 자간 −0.01em. 장식 서체를 쓰지 마라.
- 본문 15px / 1.7. 한 줄 길이는 40~45자.

## 선과 면

- **모서리 반경은 0 또는 2px.** 둥근 카드를 만들지 마라.
- 블록을 배경색으로 띄우지 말고 **1px 선으로 나눈다.** 선 색은 `--rule`.
- 그림자를 쓰지 마라. 깊이는 선의 농도로 표현한다.
- 표면이 올라가야 하는 곳은 `--ground-2` 를 쓰되, 전체의 두세 곳 이내로 제한한다.
- 여백을 4px 배수로 맞춘다. 정렬이 어긋난 것이 가장 싸구려로 보인다.

## 계측 장비의 디테일

이 요소들이 "앱"과 "장비"를 가른다. 장식이 아니라 실제로 정보를 담아야 한다.

- **눈금.** 타임라인에 국면 눈금을 긋고 그 아래 이름을 작게 단다.
  슬라이더 손잡이를 기본 모양 그대로 두지 마라.
- **기준선.** 값을 막대로 그릴 때 기준값은 채우지 말고 **세로 눈금 하나**로 표시한다.
  채운 막대와 눈금의 거리가 곧 벗어난 양이다.
- **단위 접미.** 모든 수치 옆에 단위를 단다. `°` `s` `fps` `프레임`.
- **상태를 글자로.** 아이콘만으로 상태를 말하지 마라. 이모지를 쓰지 마라.
- **고정 자리.** 수치가 바뀌어도 칸 너비가 흔들리지 않게 한다. 탭 숫자와 고정폭.

## 하지 말 것

이것들이 AI가 만든 화면의 표식이다. 하나도 쓰지 마라.

- 크림색 바탕에 세리프 제목과 테라코타 포인트
- 근접 검정에 형광 녹색 또는 주황 하나만 튀는 배색
- 보라에서 파랑으로 가는 그러데이션
- 섹션 머리의 이모지
- 모든 것을 가운데 정렬
- 모든 블록에 같은 반경과 그림자
- 카드 왼쪽의 색 막대
- 의미 없는 번호 매기기. 순서가 정보일 때만 번호를 단다

## 움직임

- 전환은 120ms 이내. 그 이상은 느리게 느껴진다.
- 화면에 들어올 때 떠오르는 연출을 넣지 마라. 처음부터 자리에 있어야 한다.
- 움직이는 것은 **스윙 재생과 궤도가 그려지는 것** 둘뿐이다.
- `prefers-reduced-motion` 을 존중한다.

## 리포트는 다르다

도구 화면은 어둡고 조작 중심이다. 리포트는 **종이에 가깝다.**

- 바탕 `#f6f4ef`, 잉크 `#1b2024`. 다크 모드도 지원한다.
- 같은 서체 가족, 같은 색 규칙(색은 벗어난 곳에만).
- 한 단 760px. 표제 아래 2px 굵은 선 하나.
- 그림은 선화로. 채우기를 최소화한다.

## 판단 기준

작업한 화면을 보고 스스로에게 물어라.

1. 색이 보이는 자리가 전부 "문제가 있는 곳" 인가
2. 수치가 전부 고정폭으로 자리가 맞는가
3. 둥근 카드와 그림자가 없는가
4. 라벨과 수치의 크기 차이가 분명한가
5. 이 화면을 다른 주제로 그대로 옮길 수 있는가 — 옮길 수 있다면 실패다.
   골프 계측에만 맞는 요소가 있어야 한다
