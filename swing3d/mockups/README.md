# 화면 시안

이 두 파일이 구현의 시각 기준이다. 브라우저로 직접 열어서 동작을 확인한 뒤 작업해라.
설명을 읽고 상상하지 말고 열어봐라.

| 파일 | 무엇 |
| --- | --- |
| `01_screen.html` | 도구 화면. 업로드부터 내려받기까지 8단계가 한 페이지에 쌓인다 |
| `02_report.html` | 분석이 끝난 뒤 사용자가 받아가는 리포트 |

## 두 화면의 성격이 다르다

도구 화면은 **쓰는 동안 보는 것**이라 어둡고 조작 중심이다.
리포트는 **끝나고 받아가서 나중에 다시 읽는 것**이라 밝은 문서다.
이 차이는 의도된 것이다. 하나로 통일하지 마라.
리포트는 라이트/다크 양쪽을 지원하고 도구 화면은 다크 전용이다.

## 그대로 가져갈 것

- 단계 구성과 순서
- 섹션 제목과 배치
- 색 약속 — 측정값 청록, 교본 기준 보라, 과장 주황. 범례 포함
- 문구의 어조. "인식 실패" 가 아니라 무엇을 하면 되는지 적는다
- 리포트의 제목이 결론인 구조. 라벨이 아니라 판정 문장을 제목으로 쓴다
- 리포트의 "재지 못한 것" 섹션. 빼지 마라
- 세 결함을 따로 나열하지 않고 연쇄로 설명하고 무엇부터 할지 지정하는 구조

## 바꿀 것

시안의 3D 영역과 스틸컷은 **2D 캔버스로 그린 대역**이다. 시안을 가볍게 유지하려고
그렇게 했다. 구현에서는 다음으로 바꾼다.

- 3D 영역 → 기존 `web/swing3d.js` 의 three.js 뷰어
- 스틸컷 → 서버가 원본 영상에서 잘라낸 실제 JPEG
- 오버레이 → 원본 `<video>` 위에 실제 좌표로 그린 관절
- 수치 → 시안의 값은 golf1 샘플에서 가져온 예시다. 실제 트랙에서 읽어라

## 시안의 코드를 그대로 쓰지 마라

시안의 자바스크립트는 보여주기용으로 짧게 쓴 것이다.
레이아웃과 CSS 는 참고하되 로직은 기존 구조에 맞춰 다시 작성해라.
