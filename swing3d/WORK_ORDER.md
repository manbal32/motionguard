# Swing3D 작업 지시서

`PRODUCT_FLOW.md` 가 제품 기준이다. 이 문서는 그것을 구현으로 옮긴 작업 목록이다.
충돌하면 `PRODUCT_FLOW.md` 를 따른다. `CODEX_TASK.md` 는 초기 문서이며 이 둘보다 낮다.

## 완료했을 때의 모습

골프를 아는 사람이 자기 스윙 영상을 올리고, 1분 안에,
**"캐스팅이 나고 있다", "골반이 안 돌아간다"** 를 3D 아바타에서 눈으로 확인하고,
무엇을 연습해야 하는지 알고 나간다. 설치 안내를 읽거나 오류를 해석할 일이 없다.

아래 다섯 단계를 순서대로 한다. 각 단계가 끝나면 멈추고 보고한다.

---

## 1단계 · 사내망에서도 돌아가게

사용자의 PC 는 회사 프록시 뒤에 있다. `storage.googleapis.com` 이 차단되어
브라우저로도 `ERR_SSL_PROTOCOL_ERROR` 가 난다. 너는 그 밖에 있으니 네가 받아서 넣어라.

1. `pose_landmarker_lite.task` 를 받아 `swing3d/models/` 에 커밋한다.
   `swing3d/.gitignore` 의 `models/` 줄을 지운다. 5MB 수준이라 LFS 는 불필요하다.
   MediaPipe 모델은 Apache 2.0 이다. 출처·버전·해시·재배포 가능 여부를
   `web/assets/LICENSES.md` 에 기록한다.
2. `swing3d/samples/` 에 10초 이하 골프 스윙 영상 한 개를 넣는다.
   저작권이 명확한 것만 쓰고 출처를 기록한다. 구하지 못하면 넣지 말고 그렇게 보고한다.
3. 설치 확인 스크립트를 만든다. `py -3 check.py` 로 Python 버전, mediapipe 설치 여부,
   모델 파일 존재, 포트 8765 점유를 확인하고 각각 조치 방법을 한국어로 출력한다.

**완료 기준** · 레포를 새로 클론한 PC 에서 네트워크를 전부 차단한 채
`py -3 server.py` 로 샘플 영상을 분석할 수 있다.

## 2단계 · 측정 정확도

### 2-1 손목 채널을 캐스팅에 쓸 수 있게

`swing_track.py` 의 `wrist` 는 팔꿈치→손목 방향을 쓴다. 이는 전완 방향이라
클럽 각도가 아니다. `LEFT_INDEX` / `RIGHT_INDEX` 가 있으면 **손목→검지** 로 바꾼다.
이 선이 클럽 샤프트를 근사하고, 전완과 이루는 각이 손목 코킹이다.

- `REQUIRED` 에 INDEX 를 선택 항목으로 추가한다. 없으면 지금 방식으로 물러선다.
- 어느 쪽을 썼는지 `meta.wrist_source` 에 `"index"` 또는 `"forearm"` 으로 기록한다.
- `"forearm"` 이면 캐스팅 판정을 금지한다. findings 검증에서 거부한다.
- `video_pose.py` 는 이미 33 랜드마크를 뽑으므로 추출은 손대지 않는다.

**완료 기준** · 샘플 영상으로 뽑은 트랙에서 `meta.wrist_source == "index"` 이고,
백스윙 탑의 손목 각이 40~90도 범위에 들어온다. 수치로 보고한다.

### 2-2 측정 신뢰도를 사용자에게 알린다

낮은 신뢰도 구간은 이미 반투명 궤도로 표시한다. 여기에 더해,
어떤 국면이 신뢰할 만한지 리포트 상단에 한 줄로 요약한다.
예: "임팩트 이후는 추적이 불안정해 판정에서 제외했습니다."

## 3단계 · Gemini 판정

이것이 마지막 빈칸이다. 가장 크다.

### 입력

- `PRODUCT_FLOW.md` 의 결함 사전에 있는 결함만 판정하게 프롬프트로 제약한다.
  사전에 없는 채널을 쓴 응답은 거부한다.
- 보내는 것은 **국면 전후 ±5표본의 좌표 수치**다. 스틸샷은 기본으로 보내지 않는다.
- 각 채널의 값과 함께 **교본 기준값**을 같이 보내 비교하게 한다.
  기준은 `swing3d.js` 의 `modelPoses` 와 동일해야 한다. 두 곳에 각각 적지 말고
  한 곳에서 읽어 쓴다.
- 입력 예산 상한 3,000 토큰. 넘으면 표본 간격을 늘려 줄인다.

### 출력

- 반드시 `findings_contract.py` 의 검증을 통과해야 한다. 통과 못 하면 거부하고
  사유를 남긴다. 재시도는 한 번만 한다.
- 결함은 최대 4개. 심각도 순으로 정렬한다.
- 각 결함에 `youtube` 검색어 2개를 한국어와 영어로 하나씩 넣는다.

### 운영

- `GEMINI_API_KEY` 가 없으면 `findings/` 의 파일을 읽는 현재 경로로 물러선다.
  오류를 내지 말고 "키가 없어 예시 판정을 보여준다" 고 화면에 표시한다.
- 429 · quota · rate limit 응답은 같은 경로로 물러선다.
- 사전 토큰 수와 응답의 실제 사용량을 구분해 기록하고 화면에서 볼 수 있게 한다.
- 원본 영상과 API 키는 어떤 경우에도 커밋하지 않는다.

**완료 기준** · 키 없이도 동작하고, 키가 있으면 샘플 영상에서 결함 1개 이상을
판정해 3D 과장까지 이어진다. 실제 요청의 입력·출력 토큰 수를 보고한다.

## 4단계 · 보는 사람이 알아볼 수 있게

지금 화면은 개발자가 보는 화면이다. 쓰는 사람이 보는 화면으로 바꾼다.

### 4-1 과장 배율

- 슬라이더 상한을 4.0 에서 **3.0** 으로 낮춘다.
- `severity` 에 따른 기본값: low 1.5 · medium 2.0 · high 2.5.
- 4배에서는 몸통이 −5도까지 가서 사람 자세가 아니게 된다. 그 선을 넘지 않는다.

### 4-2 타임라인

- 다섯 국면 위치에 눈금과 이름을 표시한다. 눌러서 이동한다.
- 현재 국면 이름을 항상 보여준다.
- 결함이 지목한 구간을 타임라인 위에 색 띠로 표시한다.

### 4-3 국면별 계측값 표

- 행: 어드레스 · 백스윙탑 · 다운스윙 · 임팩트 · 피니시
- 열: 스윙각 · 몸통회전 · 골반회전 · 기울기 · 손목
- 교본 기준값을 같은 표에 나란히 둔다. 측정값과 기준값의 서체·색을 구분한다.
- 행을 누르면 그 국면으로 이동한다.

### 4-4 표시 토글

클럽 궤도 · 관절점 · 스윙 플레인 · 국면 잔상 · 볼 추적.
국면 잔상은 탑·다운스윙·임팩트 세 자세를 반투명으로 겹쳐 보여준다.

### 4-5 진행 표시

영상 추출은 10초에서 1분 걸린다. 지금은 아무것도 보이지 않는다.
진행률 또는 단계 표시를 넣는다. 취소 버튼을 둔다.

### 4-6 오류 문구

모든 실패에 **무엇을 하면 되는지** 를 같이 적는다.
"인식 실패" 가 아니라 "전신이 화면에 들어오게 다시 찍어주세요" 로 쓴다.

## 5단계 · 보기에 부끄럽지 않게

지금 아바타는 회색 맨몸에 주황 탱크톱이다. 사람으로 보이지만 운동선수로 보이지 않는다.

### 5-1 캐릭터

- 바지 · 신발 · 상의 · 모자를 색과 재질로 구분한다. 메시 교체 없이 머티리얼로 한다.
- 피부와 천의 거칠기를 다르게 한다. 천 0.8, 피부 0.7.
- 원색을 쓰지 않는다. 채도를 낮춘다.
- 발밑 접촉 그림자를 넣는다. 인물이 떠 보이는 가장 큰 원인이다.

### 5-2 카메라

- 화각을 38도에서 **30도** 로 좁힌다. 지금은 항공 촬영처럼 보인다.
- 정면·다운더라인 프리셋의 눈높이를 1.6m 로 맞춘다.

### 5-3 환경

- 티 마커 구가 사람 머리만 하다. 실제 비율로 줄인다.
- 야간 코스에서 플러드라이트의 빛 웅덩이가 보이게 한다. 지금은 어두운 낮처럼 보인다.
- 지면을 단색 줄무늬에서 타일 텍스처로 바꾸고 미세한 높이 변화를 준다.

**완료 기준** · 세 코스 각각에서 어드레스·백스윙탑·임팩트·피니시
네 장면을 캡처해 첨부한다. 캡처를 보고 판단한다.

## 품질 기준

- **성능** · 10초 영상 추출 60초 이내, 뷰어 30fps 이상.
- **네트워크** · 외부 요청은 Gemini 호출뿐이다. 그 외 전부 로컬에서 돈다.
- **테스트** · 기존 7개를 유지하고, 새 기능마다 테스트를 추가한다.
  Gemini 는 실제 호출 없이 응답을 흉내 내 검증한다.
- **보안** · `.env` · `local-data/` · 원본 영상은 커밋하지 않는다.
  커밋 전에 `git diff --cached` 로 키 패턴을 확인한다.

## 하지 말 것

- 대화형 코치 루프를 만들지 마라. 흐름은 직선이다.
- 결함 사전에 없는 결함을 판정하게 하지 마라.
- 측정 근거가 없는 지적을 3D 로 보내지 마라. 텍스트로만 남긴다.
- 측정값과 모델값을 같은 색·같은 서체로 섞지 마라.
- SMPL 계열 모델을 쓰지 마라. 비영리 연구 라이선스다.
- 새 디렉터리를 임의로 만들지 마라.

4. 막힌 것. 우회하지 말고 무엇이 막혔는지 적어라
