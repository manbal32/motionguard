# 작업 지시 · 2D 나란히 비교를 메인으로

이 문서가 현재 유효한 지시다. `WORK_ORDER.md` 의 품질 기준 · 하지 말 것 · 보고 형식은
그대로 유효하고, 단계 목록만 이 문서가 대체한다.

---

## 방향 전환 (먼저 읽어라)

**3D 뷰어는 메인에서 빼고 보조로 내린다.** 대신 **원본 영상과 과장을 나란히 놓는
2D 비교**가 메인 화면이 된다.

이유 — 설득력은 "이게 내 스윙이다" 에서 나온다. 원본 영상 위에 측정 좌표가 찍혀
있고 바로 옆에 같은 프레임 · 같은 카메라 각도로 과장된 그림이 있으면 사용자가
자기 문제를 부인할 수 없다. 3D 는 깊이를 측정한 적이 없어서 한 겹의 의심이 남는다.

그리고 **2D 과장은 측정한 평면에서 측정한 값을 키우는 것**이다. 우리가 잰 것은
화면에 투영된 각도다. 그걸 화면 안에서 키우는 것은 정직하다. 3D 과장은 측정하지
않은 축까지 건드린다.

3D 는 카메라 각도 문제 하나만 담당한다 — 정면 촬영 영상은 스윙 플레인이 보이지
않으므로, 측정한 각도로 재구성해 다운 더 라인에서 보여준다. **"재구성" 이라고
명시하고 "깊이는 추정" 이라고 적는다.**

기존 3D 코드(`web/swing3d.js`, `web/avatar.js`, `web/assets/`)는 **삭제하지 마라.**
접힌 보조 섹션으로 이동시킨다.

## 1단계 · 교본 트랙 만들기

비교에는 비교 대상이 있어야 한다. 지금은 측정값만 있다.

`swing3d/reference_track.py` 를 새로 만든다.

- `build_reference(track)` → 측정 트랙과 **같은 표본 수 · 같은 국면 시점**을 가진
  9채널 교본 트랙을 돌려준다.
- 교본값은 `PRODUCT_FLOW.md` 의 국면별 기준값을 국면 사이에서 smoothstep 보간해
  만든다. 국면 인덱스는 측정 트랙의 것을 그대로 쓴다 — 교본이 사용자의 템포를
  따라가야 같은 시점끼리 비교된다.
- 어드레스 기준값은 **사용자의 어드레스 실측값으로 맞춘다.** 체격·카메라 거리가
  다르므로 절대값을 그대로 쓰면 전부 결함으로 잡힌다. 어드레스를 0점으로 맞추고
  그 이후의 변화량을 비교한다.
- `GET /api/reference/<트랙ID>` 로 내려준다. 응답은 측정 트랙과 동일한 스키마.

**완료 기준** — `samples/golf1_export.csv` 에 대해 어드레스 프레임에서 측정값과
교본값의 9채널 차이가 전부 2.0° 이내. 숫자로 출력해서 보고하라.

## 2단계 · 과장 계산

`swing3d/exaggerate.py` 를 새로 만든다.

```
표시값 = 교본값 + (측정값 - 교본값) × 배율
```

- 전체 값을 곱하지 마라. **차이만 증폭한다.** 교본과 같으면 과장해도 그대로다.
- 배율은 결함 구간 안에서만 적용한다. 구간 경계에서 갑자기 꺾이지 않도록
  구간 양끝 전체 길이의 1/3 만큼을 smoothstep 으로 올리고 내린다.
- 배율 상한 — severity `low` 1.5 / `medium` 2.0 / `high` 2.5 / 최대 3.0.
  사용자가 슬라이더로 1.0–3.0 을 직접 조절할 수 있게 하고, **기본값은 severity
  에서 온 값**으로 둔다.
- 1.0 배는 반드시 측정값과 정확히 같아야 한다. 이것이 신뢰 장치다 — 사용자가
  슬라이더를 1.0 으로 내려 "조작이 아니라 측정값을 키운 것" 을 직접 확인한다.
- 결함 채널만 과장한다. 나머지 8채널은 측정값 그대로 그린다.

**완료 기준** — 배율 1.0 에서 과장 트랙과 측정 트랙의 모든 채널 모든 프레임
차이가 0.001° 이내. `tests/test_exaggerate.py` 로 검증하라.

## 3단계 · 비교 화면

`web/index.html` 의 `#overlay` 섹션(03 관절 오버레이)을 **비교 뷰로 확장한다.**
새 섹션을 만들지 말고 이 섹션을 키운다.

레이아웃 — 가로 2열. 720px 이하에서는 세로로 쌓는다.

**왼쪽 · 원본 영상 + 측정 좌표**
- 기존 `<video id="original">` + `<canvas id="joints">` 를 그대로 쓴다.
- 관절점은 **얼굴 11개를 제외한 22개만** 찍는다. 반지름 2.3px 로 줄인다.
  (현재 33관절 전부 찍고 점이 크다 — 이미 지적된 결함이다)
- 교본 자세를 회색 반투명 선으로 겹쳐 그린다. 토글 버튼 `교본 겹치기`,
  기본값 켜짐. 색 `rgba(127,138,133,.75)`, 선 굵기 1.6px.
- 결함 채널에 해당하는 뼈만 주황(`--signal`)으로 두껍게(3.2배) 그린다.

**오른쪽 · 같은 시점 · 과장**
- 새 `<canvas id="exaggerated">`. 배경은 영상이 아니라 격자(28px 간격,
  `rgba(233,231,224,.045)`)다. 영상이 아님을 배경으로 구분한다.
- 과장 트랙으로 같은 뼈대를 그린다. 같은 원점 · 같은 스케일을 쓴다.
  왼쪽과 오른쪽의 골반 중심이 화면에서 같은 위치여야 한다.
- 교본 겹치기 토글은 양쪽에 동시에 적용된다.
- 섹션 헤더 캡션에 현재 배율을 `과장 2.5×` 로 표시한다.

**공유 조작부** — 지금 있는 재생 · ±1프레임 · 0.5× · 스크러버를 그대로 쓴다.
양쪽 캔버스가 **하나의 seek 값**을 따른다. 추가할 것:
- 과장 배율 슬라이더 (1.0–3.0, step 0.1) + 현재 값 표시
- `교본 겹치기` 토글
- 스크러버 눈금에 **결함 구간을 주황 띠로** 표시한다. 국면 눈금은 유지한다.

**수치 줄** — 캔버스 아래 등간격 한 줄, 모노스페이스:
`채널명 · 측정 00.0° · 교본 00.0° · 차이 00.0° · 과장 표시 00.0°`
측정은 `--ink`, 교본은 `--ref`, 과장 표시는 `--signal` 로 색을 구분한다.

**주의 문구** — 비교 뷰 바로 아래 한 줄, 모노스페이스 10.5px, `--signal`:
`오른쪽은 교육용 과장이며 측정값이 아닙니다 · 왼쪽 수치가 실제 측정입니다`

**완료 기준** — 배율 1.0 에서 두 캔버스의 뼈대가 픽셀 단위로 겹친다.
두 캔버스를 같은 프레임에서 캡처해 차분 이미지의 최대 픽셀 차이를 숫자로 보고하라.

## 4단계 · 결함 선택

비교 뷰 위에 결함 버튼 줄을 놓는다. `findings` 배열이 그대로 버튼이 된다.

- 버튼 하나 = finding 하나. 결함 이름(굵게) + `측정 00° · 교본 00°`(모노스페이스).
- 누르면 ① 해당 `range` 의 중앙 프레임으로 이동 ② 스크러버 주황 띠가 그 구간으로
  이동 ③ 하이라이트되는 뼈가 그 `channel` 의 뼈로 바뀜 ④ 배율 기본값이 그
  `severity` 값으로 바뀜.
- `channel` 과 `range` 가 없는 finding 은 버튼을 만들지 마라. 텍스트 리포트에만
  남긴다. (`findings_contract.py` 의 기존 규칙)
- 채널 → 뼈 매핑:
  `torso` → 좌우 어깨 / `hips` → 좌우 골반 / `wrist`,`swing` → 팔꿈치–손목 양쪽 /
  `lean` → 어깨중심–골반중심 / `shiftX` → 골반중심 수직선 / `kneeL`,`kneeR` →
  해당 쪽 골반–무릎 / `heelR` → 오른 발목–뒤꿈치

**완료 기준** — `findings/golf1.json` 의 finding 개수만큼 버튼이 생기고, 각 버튼이
서로 다른 구간·다른 뼈를 하이라이트한다. 버튼별 구간 값을 출력해 보고하라.

## 5단계 · 3D 를 보조로 이동

- 비교 뷰 아래에 접힌 섹션 `다른 각도에서 보기`. 헤더 우측에 `재구성` 라벨.
- 본문 한 줄 — `정면에서 찍은 영상은 스윙 플레인이 보이지 않습니다. 측정한 각도로
  3D 를 재구성해 다운 더 라인에서 볼 수 있습니다. 깊이는 측정값이 아니라 추정입니다.`
- `3D 로 열기` 버튼을 누를 때 처음으로 three.js 와 GLB 를 불러온다.
  **초기 로딩에 포함시키지 마라.** 메인 화면 첫 페인트가 빨라야 한다.
- 3D 는 비교 뷰의 seek 과 배율을 공유한다. 열어둔 채로 스크러버를 움직이면 같이 움직인다.
- 기존 webm 결함 — 궤적 리본이 사람보다 눈에 띄는 것, 공이 큰 것, 접지 그림자 없는 것,
  바다 평면 틀어진 것, 클럽헤드 재질 — 은 보조로 내려갔으니 **지금 고치지 마라.**
  3D 가 다시 메인이 될 때 다룬다.

**완료 기준** — 메인 화면 첫 페인트에서 three.js 와 GLB 가 네트워크/디스크 요청에
나타나지 않는다. 요청 목록을 보고하라.

## 6단계 · 영상 크롭

와이드샷에서 골퍼가 40px 정도로 작게 나오면 관절 오버레이가 보이지 않는다.
비교 뷰가 메인이 된 지금 이것은 선택이 아니라 필수다.

- 전체 프레임에서 감지된 랜드마크의 바운딩 박스를 구한다. 상하좌우 25% 여유를 둔다.
- 영상 전체 구간의 박스를 합집합으로 구해 **하나의 고정 크롭 영역**을 쓴다.
  프레임마다 바꾸면 화면이 흔들린다.
- 크롭 영역이 원본의 60% 보다 작을 때만 적용한다. 이미 사람이 크게 나오면 건드리지 않는다.
- 크롭은 **표시에만 적용한다.** 좌표 추출은 원본 전체 프레임에서 그대로 한다.
  (크롭된 영상을 다시 추출하면 좌표계가 달라져 트랙이 깨진다)
- 국면 스틸컷(`/api/still`)에도 같은 크롭을 적용한다. 지금 네 장이 전부 똑같이 보이는
  원인 중 하나다.

**완료 기준** — `samples/golf_swing.mp4` 에서 크롭 후 골퍼의 어깨–발목 세로 길이가
표시 캔버스 높이의 55% 이상. 측정해서 숫자로 보고하라.

## 안 건드릴 것

- `swing_track.py` 의 각도 계산 — 다운스윙/임팩트 몸통·골반이 0.0° 로 나오는 문제는
  **내(Claude)가 따로 본다.** 손대지 마라.
- 채널별 신뢰도, visibility 하한 0.5 → 0.3 — 다음 라운드다.
- Gemini 연동 — 비교 뷰가 끝난 뒤에 붙인다. 지금은 `findings/golf1.json` 고정 파일로 개발하라.

## 환경

개발 머신이 회사 Windows 에서 맥(Apple Silicon)으로 옮겨간다.
- `start.command` 가 맥에서 동작하는지 확인하라. 안 되면 고쳐라.
- 프록시 우회로 벤더링한 `web/vendor/three/` 와 커밋된 `models/*.task` 는
  **그대로 둔다.** 네트워크 없이 도는 것은 제품의 장점이다.
- `requirements.txt` 가 Apple Silicon 에서 그대로 설치되는지 확인하라.
