작성 2026-11-11 · **새 프로젝트를 백지에서 만든다.** 기존 코드베이스는 필요 없다.

영상 좌표에서 뽑은 측정 트랙으로 3D 아바타를 구동하고, 코스와 클럽을 골라 보여주는

## 1. 범위

### 하는 것

## 2. 데이터 계약 (이게 제일 중요하다)

`swing_track.py` 가 내보내는 JSON 이 서버와 뷰어 사이의 유일한 계약이다. 임의로 바꾸지 말 것.

```json
{
  "schema": "motionguard.swingtrack/1",
  "channels": ["swing","torso","hips","lean","wrist","shiftX","kneeL","kneeR","heelR"],
  "meta": {"fps":64.3,"hold":0.3,"dur":1.98,"samples":109,
           "measured":["swing","torso","hips","lean","shiftX","kneeL","kneeR","heelR"],
           "modeled":["wrist"]},
  "events": {"address":0.152,"top":0.576,"down":0.654,"impact":0.678,"finish":1.0},
  "track": [[...9개...], ...]
}
```

- `events` 값은 전체 타임라인 0~1 기준이다.
- `track` 의 각 행은 `channels` 순서를 따른다. 행 개수 = `meta.samples`.
- **`wrist` 채널은 측정값이 아니다.** 영상에 클럽이 안 잡혀 손–클럽 각도를 구할 수 없다.
  측정값은 거의 0이고, 뷰어가 스윙각에 비례한 모델값을 더해서 쓴다. UI에서 끌 수 있어야 한다.

### 서버 작업
- `GET /api/tracks` — `tracks/` 의 트랙 목록(이름, 표본 수, 길이)을 반환.
- `GET /api/track/<id>` — 트랙 JSON 하나를 반환.
- `POST /api/track` — 좌표 CSV 를 받아 `swing_track.build_track()` 으로 트랙을 만들고 `tracks/` 에 저장.
- 결과는 입력 해시로 캐시한다. 같은 입력에 두 번 계산하지 않는다.
- 랜드마크 누락·저신뢰로 트랙을 못 만들면 **빈 뷰어를 띄우지 말고** `{"ok":false,"reason":"..."}` 로 사유를 돌려준다.
  화면은 "이 영상은 3D 재현이 어렵다"와 그 사유를 그대로 보여준다.

## 3. 뷰어 리그 사양 (`web/swing3d.js`)

Three.js 0.149 UMD. 모듈 하나로 만들고, `mount(el, trackJson, opts)` / `dispose()` 만 외부에 노출한다.

### 본 구조
```
figure
└ hips  (rotation.y = hips, position.x = shiftX)
  ├ legL / legR  (knee.rotation.x = kneeL/kneeR, 오른 ankle.rotation.x = -heelR*0.9)
  └ torso  (rotation.y = torso, rotation.x = lean)
    └ chest
      ├ headG  (rotation.y = -torso*0.78 — 임팩트까지 공을 본다)
      ├ 팔 2개  ← 어깨→손 2본 IK 로 매 프레임 재배치 (상완 0.33, 전완 0.34)
      └ plane  (rotation.x = 클럽별 플레인 경사, rotation.y = -0.22)
        └ swing  (rotation.z = swing)
          └ wrist  (rotation.z = wrist)
            └ 샤프트 + 클럽헤드
```

**팔은 회전으로 돌리지 말고 IK 로 풀어라.** 어깨 위치와 손 위치만 주고 팔꿈치는 코사인법칙으로 구한다.
폴 벡터는 `(side*0.55, -1, -0.45)` 를 손 방향에 직교화해서 쓴다.
이렇게 해야 백스윙 탑에서 트레일 암이 접히고 리드 암이 펴진다 — 이게 "사람답게" 보이는 핵심이다.

### 좌표 약속
- 골퍼는 원점, +Z 를 보고 선다. 타깃 방향은 **-X**. 골퍼의 오른쪽이 +X.
- `swing` 양수 = 백스윙. `swing` 0 부근에서 클럽헤드가 지면에 닿는다.

### 공 위치는 지정하지 말 것
클럽을 바꾸거나 트랙을 바꾸면, **임팩트 시점에 클럽헤드가 실제로 지나가는 월드 좌표를 계산해서 거기에 공을 놓는다.**
하드코딩하면 클럽/사람이 바뀔 때마다 공이 허공에 뜨거나 땅에 묻힌다.

```js
applyPose(events.impact);
clubTip.getWorldPosition(v);
ball.position.set(v.x, club.tee, v.z);
```

## 4. 클럽 프리셋

측정값이 아니라 설정값이다. UI에 그렇게 표시한다.

| | 샤프트 | 플레인 경사 | 티 높이 | 발사 vy | vx | 캐리 |
|---|---|---|---|---|---|---|
| 드라이버 | 0.95 | -0.60 | 0.075 | 13.4 | -17.5 | 168 m |
| 7번 아이언 | 0.80 | -0.50 | 0.043 | 12.2 | -13.2 | 112 m |
| 웨지 | 0.70 | -0.42 | 0.043 | 11.5 | -7.4 | 58 m |

탄도는 `g=9` 포물선 + 약한 측면 가속(`vz=-1.1, az=-0.55`)으로 충분하다.
**지금은 클럽헤드 속도에서 추정하지 않는다.** 나중에 붙일 자리만 함수로 분리해 둘 것.

## 5. 카메라 — 사람이 주인공이다

공을 따라가느라 사람이 콩알만 해지면 안 된다. 실제로 한 번 그렇게 만들었다가 되돌렸다.

- 볼 추적 중 거리 증가는 **기본 거리 + 4.5 까지만**.
- 시선도 골퍼 쪽에 붙여둔다: `target.lerp(ballPos, 0.30 * u)`, y는 골퍼 아래로 내려가지 않게 클램프.
- 공은 **탄도선**으로 보여준다. 공 자체를 화면에 붙잡아 두려 하지 마라.

프리셋 4개: 정면 / 다운 더 라인 / 하이 앵글 / 손목 클로즈업. 드래그 회전, 휠 줌.

## 6. 에셋 — 여기가 네 주 작업이다

현재 아바타는 캡슐·박스 조립체다. 품질을 올려라.

### 캐릭터
- Mixamo 의 리깅된 캐릭터를 GLB 로 받아 `web/assets/` 에 둔다.
- 위 본 구조에 **리타기팅**한다. 본 이름 매핑 테이블을 코드에 상수로 박지 말고 JSON으로 분리할 것.
- **SMPL / SMPL-X / GVHMR 계열은 절대 쓰지 마라.** 비영리 연구 라이선스다. 이건 사업이다.
- 쓰는 에셋마다 출처와 라이선스를 `web/assets/LICENSES.md` 에 기록한다. 상용 가능 여부를 명시할 것.

### 코스
- 지금은 코드로 생성한 지형이다. 최소한 이것부터:
  - 페어웨이 잔디 텍스처 (반복 타일, 모잉 스트라이프 유지)
  - 벙커 모래, 그린 디테일
  - 원경 스카이박스 (제주 해안 / 가평 산악 / 야간 레인지 3종)
- 텍스처는 2048px 이하, 전체 에셋 합계 **15MB 넘기지 말 것.** 로컬 프로토타입이고 업로드 영상도 150MB까지 받는다.

### 조명
- 그림자 맵 1024, PCF Soft. 야간 코스는 포인트 라이트 4개 + 약한 앰비언트.
- 코스별로 태양 색·강도·안개 밀도가 달라야 한다. 지금 값이 기준선이니 참고만 하고 더 다듬어라.

## 9. 완료 기준

1. golf1 영상으로 `swing_track.py` 를 돌려 트랙이 나오고, 그 트랙으로 아바타가 재생된다.
2. **측정 소스의 클럽 궤도선이 완전한 원이 아니다.** 백스윙·다운스윙·폴로스루 경로가 서로 다르게 보인다.
   깔끔한 원이 나오면 트랙이 아니라 키프레임을 재생하고 있는 것이다 — 버그다.
3. 클럽을 바꾸면 공 위치·궤도 크기·캐리가 같이 바뀌고, 클럽헤드가 임팩트에서 공에 닿는다.
4. 코스 3종 전환 시 하늘·안개·조명·지형이 모두 바뀐다.
5. 기존 서버 테스트 23개가 그대로 통과한다. 3D용 테스트를 추가한다:
   - 트랙 스키마 검증 (채널 수, 이벤트 범위 0~1, 단조 증가)
   - 랜드마크 누락 입력 시 `ok:false` 반환
   - 캐시 적중 시 재계산 안 함
6. 영상 업로드 → 분석 → 3D 보기까지 **한 번도 끊기지 않고** 돌아간다.

### 에셋과 용량
- `web/assets/` 의 캐릭터 GLB·텍스처는 레포에 **같이 올린다.** 집에서 받아야 돌아간다.
- 합계 15MB 를 넘기면 Git LFS 를 쓰고, 그 경우 README 에 `git lfs install` 안내를 적어라.
- 원본 영상은 올리지 않는다. 샘플이 필요하면 10초 이하로 잘라 `samples/` 에 하나만.

### 양쪽 PC에서 돌아가게
- 가상환경은 커밋하지 않는다. 각 PC에서 따로 만든다.
  - Windows: `py -3.11 -m venv .venv` → `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`
  - macOS: `python3 -m venv .venv` → `.venv/bin/pip install -r requirements.txt`
- `requirements.txt` 를 **최신 상태로 유지**해라. 다른 PC에서 받아서 바로 안 돌아가면 그게 제일 짜증난다.
- 이 프로젝트는 Windows 에서 처음 만들어진다. **macOS 에서 clone 해서 바로 돌아가는지**를
  기준으로 경로와 스크립트를 작성해라.
- 경로를 `\` 로 하드코딩하지 말고 `pathlib.Path` 를 쓴다.
- `.gitattributes` 에 `* text=auto` 를 넣어 줄바꿈 때문에 전체 파일이 바뀐 것처럼 보이지 않게 한다.
- `start.command`(macOS) 와 같은 역할의 `start.ps1`(Windows) 을 둘 다 둔다.
