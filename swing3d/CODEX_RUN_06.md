## 1 · 좌우 나란히는 폰에서 불가능하다

숫자로 확인된 사실이다.

- 세로 영상(9:16)을 폭 390px 에 넣으면 높이가 **693px** 이다. 한 개도 안 들어간다.
- 둘을 나란히 놓으면 각각 폭 **195px**. 사람 형태가 식별되지 않는다.

**반응형으로 눌러 담지 마라. 모바일은 다른 배치를 쓴다.**

### 모바일 비교 화면 — 겹치기 + 전환

화면에 **영상 하나**만 둔다. 그 위에 과장된 자세를 겹쳐 그린다.

- 원본 영상이 배경. 그 위에 **측정 관절**(흰 선)과 **과장 자세**(에메랄드 실루엣)를 겹친다.
- 큰 버튼 하나로 `측정 1.0×` ↔ `과장 2.5×` 를 **전환**한다.
  누르고 있는 동안 과장, 떼면 측정으로 돌아오는 방식을 우선 검토하라.
- 전환할 때 몸이 **움직여서** 차이가 보인다. 작은 화면에서는 공간 차이보다
  시간 차이가 훨씬 잘 보인다. 이것이 모바일에서 과장을 전달하는 방법이다.
- 교본 잔상은 연한 선으로 같은 자리에 둔다.

전환 버튼은 **엄지가 닿는 화면 아래쪽**에 둔다. 최소 터치 영역 `44 × 44px`.

### 데스크톱도 같은 화면이다

**폭에 따라 다른 설계를 만들지 마라.** 겹치기 + 전환은 폰과 PC 모두 같다.
좌우 나란히 비교는 쓰지 않는다. 화면이 넓어지면 **영상이 커질 뿐**이다.

# 목표 화면 · `mockups/target_mobile.png`

네 화면을 그려 저장소에 넣었다. **글로 쓴 설명보다 이 그림이 정확하다.**
소스는 `mockups/target_mobile.html` 이다. 열어서 치수와 색을 그대로 가져가라.

## 핵심 — 한 페이지에 전부 쌓지 않는다

지금은 업로드 · 진행 · 비교 · 스틸컷 · 판정 · 드릴 · 내려받기가 **한 페이지에 세로로 쌓여 있다.**
PC 에서도 벽이고 폰에서는 못 쓴다. **내용을 버리는 것이 아니라 단계로 나눈다.**

```
1 / 3   업로드 · 상담      영상 썸네일(작게) + 대화 + 하단 고정 [분석하기]
2 / 3   요약 확인          네 칸 + 하단 고정 [이대로 분석] [고치기]
3 / 3   결과               비교가 화면의 주인공. 판정 목록은 그 아래로
리포트                     물어본 것 → 답 → 그림 → 먼저 할 연습 1개
```

국면 스틸컷의 숫자 표(5국면 × 6채널)는 **메인 흐름에서 뺀다.** 리포트 부록으로 보낸다.

## 화면 ③ 이 이 제품의 전부다

- 영상 **하나**가 화면을 채운다. 그 위에 교본 잔상(연한 에메랄드) + 과장 자세(진한 에메랄드)
  + 각도 호와 화살표(주황)를 겹친다.
- 상단에 **결함 이름 + `1 / 3`**. 좌우로 넘기면 다음 결함.
- 하단에 **한 줄 수치** — `백스윙 탑 · 42° 교본 24°`. 네 칸짜리 표를 넣지 마라.
- 그 아래 **배율 슬라이더**, 그 아래 **`누르고 있으면 과장` 큰 버튼**(주황, 높이 56px).
- 하단 고정으로 `리포트 보기`.

**누르고 있는 동안만 과장**이 핵심이다. 떼면 측정값으로 돌아온다.
작은 화면에서는 공간 차이보다 **시간 차이**가 훨씬 잘 보인다.

--ink #F3EFE6      --ink-2 #9DACBD   --ink-3 #64748B

- 경고색 주황은 **개선점에만**. 잘한 점과 긍정에 쓰지 마라.

## 데스크톱 — 옆으로 펴지 말고 위아래를 채운다

`6348bac` · `f67d248` 로 단계 분리는 들어왔다. 확인했다. 그런데 **반대로 틀어졌다.**

`1440 × 900` 에서 실측한 결과: 컬럼 폭 730px 은 적당한데 업로드 상자가 위 300px,
버튼이 아래 150px 에 핀으로 꽂혀 있고 **가운데 약 450px 이 죽어 있다.**
`390 × 844` 에서도 400px 넘게 빈다. 폰 배치를 PC 에 그대로 올려 둔 상태다.

**2단으로 쪼개지 마라.** 이 앱의 주인공은 영상이고, 영상은 비율이 고정이라
옆에 무엇을 놓으면 영상이 오히려 작아진다. 고칠 것은 가로가 아니라 **세로**다.

- 영상 미리보기는 **남는 높이를 받아 커진다.** 고정 높이를 쓰지 마라.
- 대화 영역이 **남는 세로를 전부 가져간다** (`flex: 1`). 비어 있는 중앙이 생기면 안 된다.
- 결과 화면의 영상은 세로를 꽉 채운다.
- 본문 컬럼 최대 폭 `840px`, 가운데 정렬. 초대형 모니터에서 글줄이 늘어나지 않게 한다.

한 줄로: **옆으로 펴는 것이 아니라 위아래로 채운다.** 폰과 PC 가 같은 한 줄 구조를 쓰고,
남는 공간은 콘텐츠가 커져서 가져간다.

# 셸 참조 구현 — 해석하지 말고 옮겨라

지난 두 번은 말로 설명해서 틀렸다. 이번엔 **동작하는 코드**를 올려 뒀다.

**`mockups/shell_reference.html`** — 브라우저로 열면 네 화면이 보인다.
`mockups/shell_reference.png` 이 그 렌더 결과다. 이 파일 상단의 CSS 가 정답이고,
`web/style.css` 는 그것과 같은 구조가 되어야 한다. 새로 발명하지 마라.

핵심은 여섯 줄이다.

```css
html, body { height: 100%; }
body { display: flex; margin: 0; }

.instrument {
  flex: 1 1 auto;
  width: min(840px, calc(100% - 32px));   /* 폭 분기는 이것 하나뿐 */
  margin-inline: auto;
  display: flex;
  flex-direction: column;
  min-height: 0;                          /* 없으면 자식이 스크롤되지 않는다 */
  padding-block: 14px max(18px, env(safe-area-inset-bottom, 0px));
}

.flow-head { flex: 0 0 auto; }            /* 머리 — 고정 */
.flow-body { flex: 1 1 auto; min-height: 0; overflow-y: auto;
             display: flex; flex-direction: column; gap: 12px; }
.flow-foot { flex: 0 0 auto; border-top: 1px solid var(--rule); }

.grow { flex: 1 1 auto; min-height: 0; }  /* 남는 높이를 가져갈 요소에 붙인다 */
```

`.grow` 를 붙이는 대상 — 화면마다 **하나씩만**:

| 화면 | `.grow` 를 받는 요소 |
|---|---|
| ① 업로드·상담 | `.media` (영상 미리보기) 와 `.chat` (대화 목록) |
| ② 요약 확인 | 마지막 편집 칸 |
| ③ 비교 | `.stage` (영상 무대) |
| ④ 리포트 | 본문 스크롤 영역 |

## 지금 코드에서 지울 것

```css
/* 삭제 */
.instrument { width: min(1240px, calc(100% - 48px)); margin: 40px auto 64px; }
@media (min-width:1280px) { .setup        { grid-template-columns: 1fr 1fr; } }
@media (min-width:1280px) { .finding-layout { grid-template-columns: 1fr 1fr; } }
```

`1240px` 과 `40px auto 64px` 때문에 셸이 뷰포트 높이를 쓰지 않는다.
이 두 값이 `1440 × 900` 의 빈 450px 을 만든 원인이다.
`min-width:1280px` 2단 분기는 통과 조건 16 과 정면으로 어긋난다. 둘 다 없앤다.
`max-width:719px` 블록과 `pointer:coarse` 블록은 **남겨도 된다** — 글자 크기와
터치 타겟만 다루고 레이아웃을 바꾸지 않는 한.

## 검증은 숫자로 보고하라

내가 참조 구현을 이 방법으로 쟀고, **네 화면 전부 최대 빈 구간 18px (2.1%)** 이 나왔다.
같은 스크립트를 `web/` 에 돌려서 같은 표를 제출하라.

```js
// 각 화면의 가장 큰 연속 빈 세로 구간
const root = document.querySelector('.instrument');
const h = root.getBoundingClientRect();
const rects = [...root.querySelectorAll('*')]
  .filter(e => e.offsetWidth > 20 && e.offsetHeight > 6)
  .map(e => e.getBoundingClientRect())
  .map(r => [r.top - h.top, r.bottom - h.top])
  .sort((a, b) => a[0] - b[0]);
let cur = 0, gap = 0;
for (const [t, b] of rects) { if (t > cur) gap = Math.max(gap, t - cur); cur = Math.max(cur, b); }
gap = Math.max(gap, h.height - cur);
console.log(Math.round(gap), (gap / h.height * 100).toFixed(1) + '%');
```

## 진짜 결함 — 비교 무대가 비어 있다

`samples/golf1_export.csv` 로 끝까지 돌리면 비교 화면 한가운데가 **통째로 검다.**
`"영상이 포함된 트랙을 열면 같은 프레임의 뼈대를 비교할 수 있습니다"` 라는
안내문만 있고 그림이 없다.

**이건 레이아웃 문제가 아니라 제품 문제다.** 좌표 트랙이 있으면 영상이 없어도
과장 아바타는 그릴 수 있다. 영상은 *왼쪽 원본 비교용*일 뿐이고,
**오른쪽 과장 아바타는 트랙만으로 성립한다.** 이 제품의 핵심이 그 그림이다.

고칠 것:

1. 트랙이 있고 영상이 없으면 **무대에 과장 아바타를 그린다.** 영상 자리는 비우지 말고
   아바타 하나가 무대를 꽉 채우게 한다 (`mockups/shell_reference.html` 화면 ③ 그대로).
2. 그 위에 **교본 잔상**(에메랄드 opacity .30, 과장 자세보다 뒤)과
   **각도 호 · 화살표**(amber)를 함께 그린다. 참조 구현에 SVG 로 들어 있다.
3. 안내문은 그림을 대체하는 자리가 아니다. 무대 아래 한 줄로 내린다.
4. `▶ 재생 도구` · `▶ 비교 항목` 접힌 항목 두 개가 무대 아래 떠 있다.
   무대가 남는 높이를 가져가고 (`.grow`), 이 둘은 발 쪽에 붙어야 한다.
