# 모바일 플레이 화면 정리

기존 직접 게임과 분석 후 자동 시뮬레이션을 모바일 한 화면에서 조작하도록 배치했다. 코스 선택과 최종 결과는 기존처럼 스크롤한다.

- 위: 코스/홀, 총 타수·스코어보드, 날씨, 더보기.
- 중앙: 기존 공통 홀 지도, 모자 쓴 작은 골퍼, 남은 거리와 샷 상태.
- 아래: 클럽·기준 거리·날씨/힘 반영 거리, 방향, 힘, 샷.
- 더보기: 전체 클럽 거리표, 소리, 되돌리기, 홀 마무리, 코스 변경. 자동 재생에서는 추정 근거·다시 시작·전체 이어보기·직접 게임 진입.
- 날씨 펼침: 예보 시간/출처·거리/방향 영향·안내도 방위 가정. 자동 재생의 바람 영향도 이곳에 유지.

게임 iframe은 부모의 남은 화면 높이를 사용한다. 기존 scrollHeight 측정이 화면을 계속 늘리는 경로를 제거했다. 창 크기와 모바일 주소창 변화에 맞춰 높이를 갱신하며, 가로 화면은 지도 옆에 조작을 둔다. 높이가 아주 낮으면 조작을 자르는 대신 스크롤을 허용한다. 기본 버튼 높이는 44px 이상이며 골퍼/그린 글자를 지도 표시 크기에 맞춘다.

지도/물리·6곳189홀·선택18홀·남녀17클럽 거리·쉬운 퍼팅·효과음·날씨·저장/스코어·벌타 안내·Gemini 타수·분석 우선 및 재방문 직접 게임·PDF 흐름을 보존한다. 새로운 모델 요청이나 개인 미디어 전송은 없다.

검증: 소스와 GitHub mirror에서 각각 Node289/289. 새 검사는 화면 전환/viewport 높이·메뉴 닫기·스코어/클럽 유지·자동 재생 상세 접기/뒤로 정리·짧은 지도 골퍼 크기·iframe 높이 반복 증가 방지를 다룬다. 기존 실제 Gemini 합성 응답으로 스코어표18행, 현재90타/개선85타 각각18홀 완료 및 종료카드, 같은 날씨 반영을 다시 확인했다. 새 Gemini 호출 없이 기존 응답만 재사용했다.

공개 검사: /, /game, /play, /round 모두200, 공통 CSS 연결, 각 모드 플래그와 기존 핵심 컨트롤, 중복ID 없음. 공개 파일167/167 SHA 일치. 처음 기본 Python UA 요청은403이었고 일반 모바일 UA 읽기 요청은200이었다.

실제 iPhone/Safari에서 픽셀 배치와 터치를 확인할 브라우저 도구는 제공되지 않았다. layout-design-example.png는 같은 홀/골퍼 SVG 모듈을 넣은 390×760·360×640 정적 배치 예시이며 실제 브라우저 스크린샷이나 기기 승인 근거가 아니다. 글자 확대/안전영역/주소창의 실제 표시에는 추가 확인이 필요하다.
