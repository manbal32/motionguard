# 작업 지시 05 · 계측 계층을 고친다

`CODEX_RUN_04.md` 의 2단계(시각)와 3단계(접촉 시트)는 **이미 끝났다.** 아바타와
접촉 시트는 그대로 두고 건드리지 마라. 이번에는 그 아래 **계측 계층**을 고친다.

`swing_track.py` 는 그동안 검토자가 쥐고 있었다. **이번 지시로 넘긴다.**

---

## 0 · 왜 과장이 안 걸렸나

`mockups/shots/contact_04.png` 의 10컷 전부 `과장 표시 0.0°` 다.
구간 앵커링(`30caea0`)은 제대로 들어갔다. 문제는 그 아래다.

**몸통 채널이 대부분의 프레임에서 `0.0°` 로 나온다.**
`exaggerate.js` 는 `if (actual === 0) return measured;` 로 빠져나가므로,
측정이 0 이면 어떤 배율에서도 과장이 걸리지 않는다. `exaggerate.js` 는 정상이다.

## 2 · 결함 네 개

### 결함 1 · 클램프가 음수를 0 으로 깎는다

`swing_track.py` 274–275 줄. 검토자가 넣은 것이다.

```python
turn = max(0.0, math.acos(...) - base_turn)
hip  = max(0.0, math.acos(...) - base_hip)
```

### 결함 2 · 기준점을 어드레스로 잡는다

`base_turn` 과 `base_hip` 이 어드레스 프레임의 값이다.
**어드레스에서 몸이 카메라에 정면이라고 가정한 것이다.** 정면 촬영에서만 맞다.

### 결함 3 · 부호를 손 위치에서 가져온다

```python
s = (sw[i] - base_sw) * back
sign = 1.0 if s >= 0 else -1.0
```

손은 피니시에서 다시 올라오므로 부호가 되돌아온다. 표 C 의 피니시 `+61.48°` 가 그것이다.
몸통은 계속 열리는데 부호만 뒤집힌다.

### 결함 4 · 신뢰도가 전부 아니면 전무다

| 샘플 | 신뢰도 0 인 표본 |
|---|---|
| A (CSV 정면) | 84 / 108 |
| C (정면 영상) | 87 / 137 |

필요한 16개 관절이 **모두** 보여야 신뢰도가 선다. 모션 블러가 있으면 전부 0 이 된다.
그 결과가 리포트의 `추적 신뢰도 0% · 낮음` 다섯 줄이다.

## 3 · 고칠 것

### 3-1 · 회전의 기준을 '카메라에 가장 정면인 순간'으로

`acos(shw[i] / shw_max)` 는 이미 **정면 대비 회전량**이다. `shw_max` 프레임이 0° 다.
어드레스를 기준으로 다시 빼지 마라. 채널 값은 어드레스가 0 이 되도록 맞추되,
**어드레스가 정면이라는 가정은 버린다.**

골반도 같다.

### 3-2 · 부호를 회전 자체에서 가져온다

손 위치를 쓰지 마라. 다음 중 테스트를 통과하는 것을 골라라.

- **어깨 좌우의 깊이 순서** — 랜드마크 `z` 의 `RIGHT_SHOULDER − LEFT_SHOULDER` 부호.
  어느 어깨가 카메라에 가까운지가 몸이 향한 쪽이다. `z` 가 없는 입력(좌표 CSV)에서는 쓸 수 없다.
- **정면 통과 시점을 기준으로 한 누적 부호** — 스윙 중 `shw` 가 최대가 되는 프레임을
  경계로 앞뒤의 부호를 반대로 둔다.

어느 쪽을 썼는지 트랙 `meta` 에 기록하라.

**요구 조건:** 백스윙 탑에서 피니시까지 부호가 **한 번만** 바뀌어야 한다.
되돌아오면 안 된다.

### 3-3 · 잴 수 없으면 0 을 내지 말고 '측정 불가' 로

**이것이 가장 중요하다.**

뒤 / 측면 촬영에서는 백스윙 동안 어깨 폭이 거의 변하지 않는다(표 B: 탑에서 6.89°).
**정보가 없는 것이지 안 돈 것이 아니다.** 0° 로 내보내면 "안 돌았다" 는 거짓이 된다.

- 어드레스 어깨폭이 `shw_max` 의 **60% 미만**이면 정면 촬영이 아니다.
  그 트랙의 `torso` · `hips` 를 **측정 불가**로 표시한다.
- 측정 불가 채널은 **findings 를 만들지 않는다.** `findings_contract.py` 에서 거부한다.
- 화면과 리포트는 `0.0°` 대신 **"이 촬영 각도에서는 측정할 수 없습니다"** 를 보여준다.
  `MVP_INTEGRATION.md` 0-B 를 따른다.
- 트랙 `meta` 에 `camera_facing` (추정한 촬영 방향)과 `unavailable` (측정 불가 채널 목록)을 넣는다.

### 3-4 · 신뢰도를 채널별로

- 전역 신뢰도 하나를 채널별 신뢰도로 바꾼다. `torso` 는 어깨 4점만,
  `kneeL` 은 왼다리 관절만 본다. 한 관절이 가려졌다고 전 채널이 0 이 되면 안 된다.
- `visibility` 하한을 `0.5` → `0.3` 으로 낮춘다.
- 기존 전역 `confidence` 채널은 **호환을 위해 남긴다.** 채널별 값의 최솟값으로 채운다.

# 추가 · 실사용 영상에서 드러난 결함 셋

사용자가 자기 실내 연습장 영상(세로 촬영)으로 직접 돌려 확인한 것이다.
영상은 개인 자료라 저장소에 없다. 증상과 수치만 적는다.

**먼저 좋은 소식:** 스윙각 채널에서 **과장이 처음으로 걸렸다.**
`측정 87.4° → 과장 표시 110.9°` (2.5×). 측정이 0 이 아니면 메커니즘은 작동한다.
결함 1–4 를 고치면 몸통·골반도 같아진다.

## 결함 5 · 국면 검출이 실제 영상에서 깨진다

사용자 영상의 검출 결과:

| 국면 | 프레임 |
|---|---|
| 어드레스 | 164 |
| 백스윙 탑 | 171 |
| 다운스윙 | **171** |
| 임팩트 | 174 |
| 피니시 | 215 |

**탑과 다운스윙이 같은 프레임이다.** 어드레스에서 탑까지 7프레임 — 60fps 기준 0.1초다.
실제 백스윙은 0.7–1.0초다. 스윙 전체를 51프레임 안에서 찾았다는 뜻이고 틀렸다.

저장소 샘플에서도 같은 종류가 보인다. `samples/golf_swing.mp4` 는
다운스윙 163 / 임팩트 164 로 **1프레임 차이**다.

### 원인

`swing_track.py` 245 줄.

```python
top = max(range(len(sw)), key=lambda i: abs(sw[i] - sw[0]))
```

**프레임 0 을 어드레스로 가정한다.** 영상 앞에 준비 동작 · 왜글 · 걸어 들어오는 구간이
있으면 기준이 어긋나고, 국부적인 손 움직임이 탑으로 잡힌다.

### 할 일

- 프레임 0 가정을 버린다. 손 위치 신호에서 **가장 크고 연속적인 단일 스윙 구간**을 먼저 찾고,
  그 구간 안에서 국면을 잡는다.
- 국면 사이 **최소 간격을 강제**한다. 어드레스→탑 최소 `0.30초`, 탑→임팩트 최소 `0.15초`,
  임팩트→피니시 최소 `0.20초`. fps 로 환산해 프레임 수로 쓴다.
- 조건을 못 채우면 **0 을 내지 말고** "영상에서 스윙을 찾지 못했습니다. 어드레스부터
  피니시까지 한 번의 스윙이 담기도록 잘라서 올려 주세요" 로 실패시킨다.

## 결함 6 · 관절 오버레이가 영상과 어긋난다

세로 영상에서 왼쪽 패널의 스켈레톤이 사람 몸 위에 얹히지 않는다.
어깨선이 실제 어깨보다 **위로 뜨고**, 다리 선이 실제보다 **길게** 그려진다.

### 원인 후보

캔버스 좌표 매핑이 가로 영상을 가정하거나, `overlay_crop` 적용 시 종횡비 보정이 빠졌다.
`instrument.js` 의 좌표 → 화면 변환을 `videoWidth` / `videoHeight` / 표시 크기 /
크롭을 모두 반영하도록 고친다.

### 완료 기준

가로(`samples/golf_swing.mp4`)와 세로 두 경우 모두에서,
**어깨 2점 · 골반 2점 · 발목 2점**의 오버레이 좌표가 영상 속 해당 부위와
**영상 높이의 2% 이내**로 일치해야 한다. 여섯 점의 오차를 출력하라.

세로 테스트용으로 기존 샘플을 9:16 으로 잘라
`samples/golf_swing_portrait.mp4` 로 만들어 커밋한다. 개인 영상을 쓰지 마라.

## 결함 7 · 세로 영상에서 화면이 한눈에 안 들어온다

세로 영상이 패널을 꽉 채워서 **좌우 비교와 수치 줄이 같은 화면에 안 보인다.**
사용자가 스크롤을 해야 숫자를 본다. 비교 화면의 요점은 둘을 **동시에** 보는 것이다.

### 할 일

- 비교 영역의 최대 높이를 **뷰포트 높이의 60%** 로 제한한다. 세로 영상은 그 안에 맞춘다.
- 세로 영상이어도 좌우 2단을 유지한다. 각 패널 폭을 줄여서 맞춘다.
- **수치 줄과 과장 배율 슬라이더가 비교 영역과 같은 화면에** 있어야 한다.
- 판정 카드가 비교 영역을 밀어내지 않게 한다.

### 완료 기준

`1440×900`(노트북)과 `390×844`(휴대폰) 두 뷰포트에서,
**원본 패널 · 과장 패널 · 수치 줄 · 배율 슬라이더가 스크롤 없이 동시에** 보인다.
두 뷰포트의 스크린샷을 `mockups/shots/layout_05_desktop.png`,
`mockups/shots/layout_05_mobile.png` 로 커밋하라.

## 작업 순서

결함 **5 → 1 → 2 → 3 → 4 → 6 → 7** 순서로 한다.
국면이 틀리면 나머지 측정이 전부 엉뚱한 프레임에서 나오므로 5번이 가장 먼저다.
