# 작업 지시 04 · 오른쪽 패널을 제품으로 만든다

이 문서가 이번 작업의 유일한 지시다. `REVIEW_03.md` 는 **진단 근거**로 읽고,
작업 항목은 이 문서를 따른다. `MVP_INTEGRATION.md` 의 제품 요구와 `AGENTS.md` 의
보안 · 동기화 규칙은 그대로 유효하다.

**기존 기능을 삭제하거나 되돌리지 마라.** 상담 · 요약 승인 · 33점 계측 · 잘한 점과
개선점 · 유튜브 · PDF · 보조 3D 는 전부 유지한 채 누적 개선한다.

## 0 · 지금 무엇이 문제인가

`mockups/shots/01_base.png` 를 열어 보라. 이것이 현재 제품이다.

- 수치 줄: `측정 0.0° · 교본 -28.0° · 차이 28.0° · 과장 표시 0.0°`
  → **배율 2.0 인데 과장이 0이다.**
- 오른쪽 패널: 회색 격자 위의 회색 인형. 클럽 없음, 각도 호 없음, 교본 잔상 없음.
- 왼쪽 사람은 임팩트에서 숙이고 있는데 오른쪽은 정면으로 서 있다.
  → **같은 순간의 같은 사람으로 보이지 않는다.**

이 화면이 제품의 전부다. 여기가 안 되면 나머지가 다 돼도 미완성이다.

## 1 · 먼저 · 과장이 화면에 나타나게 한다

**이것을 먼저 고친다. 이것이 안 되면 2단계의 결과를 판단할 수 없다.**

### 원인

국면과 결함 구간이 서로 다른 좌표계에 있다.

| 무엇 | 단위 | 코드 |
|---|---|---|
| 국면 이동 | 원본 **프레임 번호** | `instrument.js` 국면 버튼 → `phase_frames[key]` |
| 결함 구간 | **정규 시간 0–1** | `exaggerate.js` → `finding.range` |

국면 버튼을 누르면 결함 구간 밖으로 나가 `envelope = 0` 이 되고, 과장 표시가
측정값과 같아진다. **사용자가 가장 보고 싶은 프레임에서 아무 일도 일어나지 않는다.**

`exaggerate.js` 의 계산 자체는 정상이다. 구간 안에서는 2.5× 에 31.57° → 17.49°
(−14.08°) 로 움직인다. **계산을 고치지 마라.**

### 할 일

`findings` 항목이 국면에 직접 붙도록 한다.

```json
{ "channel": "torso", "phase": "top", "span_frames": 8 }
```

- 구간은 런타임에 `phase_frames[phase] ± span_frames` 로 계산한다.
- `phase` 가 있으면 그것을 쓰고, 없으면 기존 `range` 로 물러선다. **`range` 를 제거하지 마라.**
- `findings/golf1.json` 과 `findings/sample.json` 에 `phase` 와 `span_frames` 를 넣는다.
- `coach.py` 의 분석 응답 스키마와 `findings_contract.py` 검증에도 두 필드를 추가한다.
  `phase` 는 `address|top|down|impact|finish` 중 하나만 허용한다.

### 통과 조건

국면 버튼 5개를 차례로 누르며 각 프레임에서 `과장 표시 − 측정` 을 출력하라.
**해당 결함의 국면에서 2.5× 기준 절댓값 8° 이상.** 숫자 5개를 전부 보고하라.

## 2 · 그 다음 · 오른쪽 패널을 목표 그림처럼 만든다

**목표 그림: `mockups/target_2d.jpg`**

저장소에 넣어 두었다. 열어서 보고 그것처럼 만들어라. 글로 쓴 어떤 설명보다
그 그림이 정확하다. 세 칸 중 **가운데(1.0× 자세)와 오른쪽(차이 강조)** 이 우리가
만들 오른쪽 패널이다.

### 그림에서 가져올 것

| 요소 | 지금 | 목표 |
|---|---|---|
| 인물 | 회색 반투명 덩어리 | **솔리드 실루엣**. 윤곽선이 있고 몸통 · 팔 · 다리가 구분된다 |
| 머리 | 회색 타원 | **모자를 포함한 머리 윤곽**. 얼굴 방향은 신뢰도가 설 때만 |
| 클럽 | 없음 | **샤프트와 헤드**. 손목→검지 방향으로 그린다 |
| 교본 | 겹치기 토글에만 | **연한 잔상**을 인물 뒤에 둔다 |
| 차이 | 없음 | **각도 호 + 방향 화살표**를 결함 부위에 둔다 |
| 배경 | 격자 | **단색 + 바닥선** 하나 |

### 색

지금 앱의 어두운 바탕은 유지해도 된다. 다만 **회색 위의 회색을 끝낸다.**

- 인물 : 에메랄드 솔리드 `#2E8B74`, 윤곽선 `#1F6B58`
- 교본 잔상 : 같은 색 투명도 `0.28`
- 결함 강조 (각도 호 · 화살표 · 해당 뼈) : 기존 `--signal` 주황
- 잘한 점 선택 시 : **강조색을 쓰지 마라.** 무채색 + `유지` 라벨

경고색과 칭찬이 같은 색을 쓰면 안 된다.

### 스탠스 보존

`MVP_INTEGRATION.md` 0-A 2항 그대로다. 오른쪽 인물은 교본 복제가 아니라
**그 사용자의 해당 프레임 랜드마크**에서 출발한다. 1.0× 에서 발 위치 · 스탠스 폭 ·
골반 · 어깨 높이 · 상하체 비율이 왼쪽과 같아야 한다.

### 회전 표현에 대한 주의

`torso` · `hips` · `lean` 은 **폭 · 길이 단축률에서 역산한 값**이다. 즉 화면 밖으로의
회전이다. 지금 `project()` 는 이것을 화면 안 회전으로 적용해서, 결과가
**"덜 돌았다"가 아니라 "옆으로 기울었다"로 보인다.**

이번에 이 변환을 새로 설계하지 마라. 대신 **각도 호 · 화살표 · 교본 잔상으로 차이를
드러내고**, 관절 변형만으로 표현이 제한되는 경우 화면에 그 사실을 한 줄로 적는다.
목표 그림의 세 번째 칸이 정확히 그 방식이다.

측정하지 않은 움직임을 사실처럼 만들지 마라.

`tests/contact_sheet.py` 를 만든다. Playwright 로 서버를 띄우고

### 통과 조건 — 숫자 세 개

1. **1.0× 정합** — 1.0× 에서 좌우 인물의 발 · 골반 · 어깨 6개 앵커의 화면 좌표 차이.
   **평균 4px 이하.**
2. **2.5× 가시성** — 결함 국면에서 1.0× 대비 2.5× 의 채널 변화량.
   **절댓값 8° 이상.** 그리고 강조 부위 관절의 화면 이동량 **20px 이상.**
3. **비선택 부위 보존** — 같은 비교에서 발 · 골반 앵커의 이동량 **6px 이하.**
   뼈 길이 변화 **3% 이하.**

세 숫자를 전부 출력해 보고하라. 하나라도 못 넘기면 미완성이다.

## 실행 환경 · 로컬 클론 없이 진행하는 경우

이 작업은 저장소에서 바로 진행해도 된다. 로컬에 받아 둔 것이 없어도 막히지 않는다.

- 작업 브랜치는 `feature/swing3d` 다. 끝나면 **같은 브랜치에 push** 하고 원격 SHA 를 보고한다.
  PR 로 올릴 거면 base 를 `feature/swing3d` 로 둔다. `main` 에 직접 올리지 마라.
- **`GEMINI_API_KEY` 가 없어도 된다.** 이번 작업은 고정 판정 파일
  (`findings/golf1.json`, `findings/sample.json`)로 진행한다. 키가 없으면 상담 · 요약은
  데모 모드로 떨어지는데 그대로 두면 된다. **키를 요구하거나 만들어 넣지 마라.**
- 모델(`models/pose_landmarker_lite.task`), 샘플 영상(`samples/golf_swing.mp4`),
  three.js 와 폰트는 **이미 저장소에 있다.** 내려받지 말고 그대로 쓴다.
- 파이썬 의존성은 `swing3d/requirements.txt` 로 설치한다.
