## 0. 이 제품이 무엇인가

골프 스윙 영상을 올리면,

1. 상담으로 **무엇이 고민인지** 듣고,
2. 영상에서 **33점 자세를 계측**하고,
3. 교본과 다른 부분을 **조금 과장해서 눈에 보이게** 만들고,
4. 고객의 말로 된 **리포트**를 주고,
5. 다음에 다시 찍으면 **개선된 부분을 누적**해 관리한다.

**과장이 제품의 핵심이다.** 사람은 12도 차이를 못 본다. 2.5배로 과장하면 본다.
2D냐 3D냐는 수단일 뿐이고, 화면에서 차이가 안 보이면 이 제품은 아직 미완성이다.

장기 목표는 선수 기준 데이터와 비교해 필드별 시뮬레이션으로 예상 타수까지
가는 것이다. 이번 범위는 **정보 제공까지**다. 그래도 계획에서 삭제하지 않는다.

# 1단계 — 인물 크롭 후 자세를 다시 뽑는다

## 할 일

자세 추출을 **2패스**로 바꾼다.

**1패스 — 인물 찾기**
지금처럼 전체 프레임에서 자세를 뽑는다. 목적은 측정이 아니라 위치 파악이다.

**박스 계산**
1패스 결과 중 **해부학 필터를 통과한 관측만** 모아 바운딩 박스를 구한다.

- 스윙 **전체**를 감싸는 **고정 박스**를 쓴다. 프레임마다 다른 박스를 쓰면
  재생할 때 화면이 확대·이동하며 흔들린다.
- 여유는 상하좌우 각 **25%**
- 박스는 **정사각형**으로 맞춘다 (가로세로 비율 왜곡 방지)
- 박스가 원본 밖으로 나가면 원본 경계로 자르되, 비율은 유지한다

**2패스 — 다시 뽑기**
각 프레임을 그 박스로 잘라 **한 변 640px 이상**으로 확대한 뒤 자세를 다시 뽑는다.
**계측에는 이 결과만 쓴다.**

**좌표 역변환**
2패스 좌표는 크롭 기준이다. 화면 오버레이·스틸컷에 쓰려면 원본으로 되돌려야 한다.

```
x_orig = box_x + x_crop * box_w
y_orig = box_y + y_crop * box_h
```

역변환 함수와 박스 값을 트랙 `meta.crop_box` 에 저장한다.
**이 역변환이 틀리면 4단계 오버레이가 전부 어긋난다.**

`person_crops` 의 박스 로직을 재사용하되 스틸 전용에서 분리해
추출 경로에서도 쓸 수 있게 한다.

## 성능

2패스는 추출을 두 번 한다. 1패스는 **3프레임에 1번만** 돌려도 박스를 구하는 데
충분하다. 그렇게 해서 전체 시간이 기존 대비 1.6배를 넘지 않게 한다.

## 검증 명령

```bash
cd swing3d
python3 - <<'PY'
import video_pose, swing_track as st
for v in ("samples/golf_swing.mp4", "samples/golf_swing_portrait.mp4"):
    frames, fps = video_pose.extract(v)[:2]
    t = st.build_track(frames, fps); m = t["meta"]
    print(v)
    print("  usable =", m.get("usable"), "| camera =", m.get("camera_facing"),
          "| 폭비 =", m.get("address_shoulder_width_ratio"))
    print("  채택 =", m.get("accepted_frames"), "/", m.get("total_frames"),
          "| 어깨폭 최대 =", m.get("shoulder_width_max"),
          "| crop_box =", m.get("crop_box"))
    pf, f = m.get("phase_frames") or {}, m["fps"]
    k = list(pf)
    for a, b in zip(k, k[1:]):
        print(f"  {a:8s}->{b:8s} {pf[a]:4d}->{pf[b]:4d}  {(pf[b]-pf[a])/f:5.2f}s")
    print("  국면별 몸통/골반:", {p: (round(t['track'][i][1],2), round(t['track'][i][2],2))
          for p, i in (pf or {}).items() if i < len(t['track'])})
PY
```

# 2단계 — 촬영 품질 안내

1단계를 해도 못 쓰는 영상은 들어온다. **0을 내지 말고 사람 말로 안내한다.**

## 상태와 문구

| 상태 | 조건 | 문구 |
|---|---|---|
| `too_far` | 2패스 어깨폭 최대 < 0.20 | 촬영 거리가 멀어 몸의 회전을 잴 수 없습니다. 몸 전체가 화면 높이의 3분의 2를 채우도록 다시 찍어 주세요. |
| `tracking_failed` | 채택률 < 50% | 영상이 흔들리거나 인물이 가려져 자세를 추적하지 못했습니다. 고정된 위치에서 다시 찍어 주세요. |
| `no_swing` | 국면 5개 확정 실패 | 스윙 한 번이 처음부터 끝까지 담기지 않았습니다. 어드레스부터 피니시까지 한 번만 담아 주세요. |
| `oblique` | `camera_facing != front` | 정면이 아니어서 몸통·골반 회전은 생략했습니다. 나머지 항목은 그대로 보여 드립니다. |

**`oblique` 는 분석을 막지 않는다.** 측정 가능한 채널은 계속 보여준다.
나머지 셋은 분석을 멈추고 안내 화면을 보여준다.

## 응답 형식

```json
"meta": {
  "usable": false,
  "unusable_reason": "too_far",
  "guidance": "촬영 거리가 멀어 ...",
  "unavailable": ["torso", "hips"]
}
```

## 화면

안내 문구 + **"다시 찍기"** 버튼(주요 버튼 규격) + 올바른 촬영 예시 그림 한 장.
예시 그림은 `mockups/` 에 SVG 로 새로 그린다 — 사람 실루엣이 화면 높이의
2/3를 채우고, 카메라가 정면에 있는 그림. 사진을 쓰지 마라.

## 통과 조건 — 2단계

| 항목 | 기준 |
|---|---|
| 네 상태 단위 테스트 | 각각 합성 좌표로 재현되고 올바른 `unusable_reason` 반환 |
| `oblique` 동작 | 분석이 계속되고 `torso`/`hips` 만 `null` |
| 화면 | 네 상태 각각 스크린샷 제출 |
| LLM 호출 | `usable:false` 일 때 호출 전에 차단될 것 |

# 3단계 — 과장 시각화

지금은 과장 아바타 **하나만** 그린다. 무엇이 얼마나 잘못됐는지 안 보인다.

## 세 겹을 겹쳐 그린다

| 층 | 내용 | 색 | 불투명도 |
|---|---|---|---|
| 뒤 | **교본 자세** (정답) | `#58C9A3` | 0.30 |
| 앞 | **과장된 내 자세** | `#58C9A3` | 0.92 |
| 위 | **각도 호 + 화살표** | `#E8A33D` | 1.0 |

### 규칙

- 두 자세는 **골반 중점을 맞춰** 겹친다. 옆으로 떼어 놓지 않는다
- 각도 호는 **차이가 나는 관절에만** 그린다. 반지름은 그 뼈 길이의 **45%**
- 화살표는 **교본 쪽을 가리킨다** — 어느 방향으로 고쳐야 하는지
- **한 번에 한 항목만** 그린다. 여러 개를 동시에 그리면 못 읽는다
- 무대 아래 한 줄 수치: `백스윙 탑 · 42° 교본 24°`
  측정값은 `#E8A33D` 굵게, 교본은 `#64748B`
- 사람형 아바타는 **머리와 몸통이 있어야 한다.** 가느다란 막대 그림 금지

참조 구현이 저장소에 있다 — **`mockups/shell_reference.html` 의 화면 ③**,
`mockups/target_2d.jpg`, `mockups/target_mobile.html`. SVG 로 들어 있으니
그대로 가져다 쓰면 된다.

## 과장 공식

```
표시값 = 교본 + (측정 − 교본) × 배율
```

부호를 보존하는 soft clamp 를 유지한다. **부호를 임의로 뒤집지 마라.**
과장이 교본을 넘어가 반대로 꺾이면 틀린 것이다.

## 과장 크기

현재 2.5배에서 관절이 **6.70px** 움직인다. 눈에 안 보인다.
`exaggerate.js` 의 채널별 `limits` 와 `project()` 의 변형 제한
(뼈 길이의 15%)이 원인이다. **제한을 뼈 길이의 40%까지 올린다.**

## 조작

| 항목 | 동작 |
|---|---|
| 배율 슬라이더 | 1.0× ~ 2.5× 연속 |
| 과장 버튼 | **누르고 있는 동안만** 과장. 떼면 실제 자세로 |
| 국면 이동 | 어드레스 / 탑 / 다운 / 임팩트 / 피니시 5버튼 |
| 구간 반복 | 해당 국면 ±0.4초 반복 재생 |
| 0.5배속 | 유지 |

## 통과 조건 — 3단계

| 항목 | 기준 | 실측 |
|---|---|---|
| 2.5배 최대 관절 이동 | **20px 이상** (390px 폭 캔버스) | |
| 1.0배 vs 2.5배 | 같은 프레임 두 캔버스의 픽셀 차이 ≥ 3% | |
| 교본 잔상 | 과장 자세와 구분되어 보일 것 (스크린샷) | |
| 각도 호 | 차이 나는 관절에 그려질 것 (스크린샷) | |
| 부호 | 과장 방향 = 측정 방향, 교본 초과 반전 없음 | |
| 아바타 | 머리·몸통 포함 | |

# 4단계 — 화면 구조와 디자인

## 기준 치수

| 항목 | 값 |
|---|---|
| 기준 화면 | **모바일 390 × 844** |
| 확인 화면 | PC **1440 × 900** |
| 본문 최대 폭 | **840px**, 가운데 정렬 |
| 좌우 여백 | 16px |
| **폭에 따른 레이아웃 분기** | **없다.** 최대 폭 제한 하나뿐 |
| 셸 | `min-height:100dvh` 세로 flex |

**PC에서 옆으로 펴지 말고 위아래를 채운다.** 같은 구성·같은 조작이
두 폭에서 동일해야 한다. 글자 크기와 터치 영역만 달라져도 된다.

셸 CSS 는 **`mockups/shell_reference.html` 상단에 그대로 있다.
해석하지 말고 옮겨라.** 핵심은 이것이다.

```css

body { display: flex; margin: 0; }

.instrument {
  flex: 1 1 auto;
  width: min(840px, calc(100% - 32px));
  margin-inline: auto;
  display: flex; flex-direction: column;
  min-height: 0;
  padding-block: 14px max(18px, env(safe-area-inset-bottom, 0px));
}
.flow-head { flex: 0 0 auto; }
.flow-body { flex: 1 1 auto; min-height: 0; overflow-y: auto;
             display: flex; flex-direction: column; gap: 12px; }
.flow-foot { flex: 0 0 auto; border-top: 1px solid var(--rule); }
.grow      { flex: 1 1 auto; min-height: 0; }
```

**`.grow` 는 화면마다 정해진 요소에만 붙인다.** 전부 늘리면 빈 카드가 거대해진다.

| 화면 | `.grow` 를 받는 요소 |
|---|---|
| ① 업로드·상담 | 영상 미리보기, 대화 목록 |
| ② 요약 확인 | 마지막 편집 칸 **하나만** |
| ③ 비교 | 무대 |
| ④ 리포트 | 본문 스크롤 영역 |

## 비율

| 요소 | 비율 |
|---|---|
| 영상 미리보기 | 원본 비율 유지 `object-fit: contain`. **세로 영상은 세로로 커진다** |
| 영상·아바타 무대 | 남는 높이를 **전부** 받는다 |
| 아바타 캔버스 | 무대와 같은 비율. `devicePixelRatio` 적용 |
| 국면 스틸컷 | **3 : 4** |
| 리포트 인쇄 | **A4 210 × 297mm**, 여백 18mm |

## 화면별 구성

### ① 업로드·상담
머리(로고 + `1 / 3`) · 영상 미리보기 `.grow` · 제목 "어디가 고민이세요?" ·
대화 목록 `.grow` · 입력창 + 전송 · 발: **분석하기**(주요)

내 말풍선 `--em-dim #2F7F69` 바탕 오른쪽, AI 말풍선 `--panel` 왼쪽,
최대 폭 84%, 반경 14px(꼬리 쪽 4px).

### ② 요약 확인
제목 "이렇게 이해했어요" · 보조 설명 ·
카드 4개(고민 / 개선하고 싶은 것 / 본인이 생각한 원인 / 연습 목표) ·
**카드는 내용 높이만** 차지한다 · 마지막 칸만 `.grow` ·
개인정보 안내 한 줄 · 발: **이대로 분석**(주요) + **고치기**(보조)

### ③ 비교
머리 · 무대 `.grow` — 교본 잔상 + 과장 자세 + 각도 호,
좌상단에 항목명과 `1 / 3`, 하단에 수치 한 줄과 배율 슬라이더 ·
**과장 버튼**(56px 앰버) · 국면 5버튼 · 이전/다음 페이저 ·
발: **리포트 보기**(보조)

### ④ 리포트
5단계 참조. 본문 `.grow` 스크롤 · 발: **PDF 저장**(주요) + **다시 분석**(보조)

## 빈 공간 측정

`tools/pxgap.py` 로 측정한다. **DOM 이 아니라 실제로 그려진 픽셀 기준이다.**
DOM 기준으로는 빈 컨테이너가 "채워진 것"으로 집계되어 빈 화면이 통과한다.
실제로 그런 일이 있었다 — DOM 2.4% 통과 / 픽셀 43.6% 실패.

```bash
python tools/pxgap.py mockups/shots/w03_m3_compare.png
```

## 통과 조건 — 4단계

# 5단계 — 리포트를 고객 언어로

지금 리포트는 좌표와 내부 지표를 나열한다. 고객이 쓸 수 없다.

## 순서 (위에서부터)

| 순 | 내용 |
|---|---|
| 1 | **고객이 말한 고민** — 승인된 요약에서 그대로, 한 줄 |
| 2 | **그에 대한 답** — 영상에서 확인된 것, 2~3문장. 숫자는 문장 안에 |
| 3 | **잘한 점** 1~2개 |
| 4 | **고칠 점 최대 3개** — 각각 ⟨국면 스틸컷 + 과장 그림 + 한 줄 수치 + 연습법 한 줄⟩ |
| 5 | **연습 영상** — 3·4번 항목에 맞춘 YouTube 링크 |
| 6 | **부록** — 전체 수치표. **마지막 페이지** |

## 문장 규칙

- 2번은 고객이 **물어본 것에 대한 답**이어야 한다.
  고민이 "백스윙이 안 된다"면 백스윙 이야기로 시작한다
- 수치는 문장 안에 녹인다 — `백스윙 탑에서 몸통이 42도 돌아갑니다. 교본은 24도입니다`
- 확정 못 하면 **무엇이 보였는지**를 쓴다.
  `자기보고의 원인을 영상에서 확정할 수 없습니다` 로 끝내지 마라

## 금지

- `추적 신뢰도 0%` 등 내부 지표를 본문에 쓰지 않는다 (부록에만)
- **차이가 0인 항목을 피드백으로 쓰지 않는다**
- 프레임 번호 · 정규화 좌표 · 채널 영문명을 본문에 쓰지 않는다
- 9칸 각도표를 1페이지에 넣지 않는다

## 통과 조건 — 5단계

| 항목 | 기준 |
|---|---|
| 1페이지 | 1·2번이 들어갈 것 |
| 고칠 점 | 4개 이상이면 심각도 상위 3개만 |
| 본문 문자열 검사 | `신뢰도`, `프레임`, `정규화`, `채널` 이 본문에 없을 것 (테스트) |
| 0 차이 항목 | 피드백 목록에 없을 것 (테스트) |
| PDF | 실제 샘플로 만든 1부를 `mockups/shots/w03_report.pdf` 로 제출 |
| 인쇄 | A4 세로, 여백 18mm, 페이지 넘김에서 항목이 잘리지 않을 것 |
