# 1단계 — 인물 크롭 후 자세를 다시 뽑는다

## 원인

PR #2 가 보고한 값이다. 채택 관측의 **원본 어깨폭 최대값이 0.034**(정규화 x).
640px 폭 영상에서 **두 어깨 사이가 약 22픽셀**이라는 뜻이다.

22픽셀로는 어깨폭 단축으로 몸통 회전을 역산할 수 없다. 1~2픽셀 흔들림이
각도로는 수십 도가 된다. 지금까지의 모든 증상 — 발목이 어깨 위로 올라가는
뒤집힌 골격, 신뢰도 0, 국면 미검출, 말이 안 되는 폭비 — 이 하나에서 나온다.

**`video_pose.py` 에 크롭 코드가 이미 있다**(`person_crops`, `phase_jpegs`).
그런데 그건 **스틸컷 저장에만** 쓰이고, 자세 추출은 원본 전체 프레임에 대고 돈다.

## 할 일

자세 추출을 **2패스**로 바꾼다.

1. **1패스** — 지금처럼 전체 프레임에서 자세를 뽑는다. 목적은 측정이 아니라
   **인물 위치를 찾는 것**이다.
2. 1패스 결과에서 **채택된 관측만** 모아 인물 바운딩 박스를 구한다.
   스윙 전체를 감싸는 고정 박스를 쓴다(스윙 중 확대/이동이 생기면 안 된다).
   여유는 상하좌우 각 25%. 박스는 **정사각형**으로 맞춘다.
3. **2패스** — 각 프레임을 그 박스로 잘라 **한 변 640px 이상**으로 확대한 뒤
   자세를 다시 뽑는다. **이 결과만 계측에 쓴다.**
4. 2패스 좌표는 크롭 기준이다. 화면 오버레이에 쓰려면 원본 좌표로 되돌려야 한다.
   `x_orig = box_x + x_crop * box_w` 형태의 역변환을 함께 저장한다.
   **이 역변환이 틀리면 4단계 오버레이가 전부 어긋난다.**

`person_crops` 의 박스 계산 로직을 재사용하되, 스틸 전용이 아니라
추출 경로에서 쓸 수 있게 분리한다.

## 통과 조건

```bash
cd swing3d
python3 - <<'PY'
import video_pose, swing_track as st
for v in ("samples/golf_swing.mp4", "samples/golf_swing_portrait.mp4"):
    frames, fps = video_pose.extract(v)[:2]
    t = st.build_track(frames, fps); m = t["meta"]
    print(v)
    print("  usable =", m.get("usable"), "| camera =", m.get("camera_facing"),
          "| 폭비 =", m.get("address_shoulder_width_ratio"))
    print("  채택 =", m.get("accepted_frames"), "/", m.get("total_frames"),
          "| 어깨폭 최대 =", m.get("shoulder_width_max"))
    pf, f = m.get("phase_frames") or {}, m["fps"]
    k = list(pf)
    for a, b in zip(k, k[1:]):
        print(f"  {a:8s}->{b:8s} {pf[a]:4d}->{pf[b]:4d}  {(pf[b]-pf[a])/f:5.2f}s")
PY
```

| 항목 | 기준 |
|---|---|
| 2패스 어깨폭 최대값 | **0.20 이상** (현재 0.034) |
| 채택 프레임 비율 | 두 샘플 모두 70% 이상 |
| 국면 | 5개 모두 확정될 것 |
| `top → impact` | 0.15초 ~ 1.50초 |
| `down` 위치 | `top→impact` 의 25%~75% |
| `address` 손 y | `top` 손 y 보다 클 것 |
| 좌표 역변환 | 2패스 좌표를 원본으로 되돌린 어깨 중점이 1패스 어깨 중점과 **0.05 이내** |
| 기존 테스트 | `python3 -m pytest tests/ -q` 통과 |

**이 단계가 통과하지 못하면 2~5단계를 하지 말고 거기서 PR 을 올려라.**
숫자를 맞추려고 임계값을 조정하거나 샘플별 예외를 넣지 마라.
PR #1, #2 처럼 미통과를 그대로 적으면 된다.

# 2단계 — 촬영 품질 안내

1단계를 해도 못 쓰는 영상은 들어온다. 그때 **0을 내지 말고 사람 말로 안내한다.**

| 상태 | 조건 | 사용자에게 보여줄 문구 |

| 인물이 너무 작음 | 2패스 어깨폭 최대 < 0.20 | 촬영 거리가 멀어 몸의 회전을 잴 수 없습니다. 몸 전체가 화면 높이의 3분의 2를 채우도록 다시 찍어 주세요. |
| 추적 실패 | 채택률 < 50% | 영상이 흔들리거나 인물이 가려져 자세를 추적하지 못했습니다. 고정된 위치에서 다시 찍어 주세요. |

# 3단계 — 과장 시각화

지금은 과장 아바타 **하나만** 그린다. 그래서 무엇이 얼마나 잘못됐는지 안 보인다.
**세 겹을 겹쳐 그린다.**

| 층 | 내용 | 색 | 불투명도 |
|---|---|---|---|
| 뒤 | **교본 자세** (정답) | `--em` `#58C9A3` | 0.30 |
| 앞 | **과장된 내 자세** | `--em` `#58C9A3` | 0.92 |
| 위 | **각도 호 + 화살표** (차이가 나는 관절) | `--amber` `#E8A33D` | 1.0 |

- 두 자세는 **골반 중점을 맞춰** 겹친다. 평행이동시키지 않는다.
- 각도 호는 차이가 나는 관절에만 그린다. 호의 반지름은 그 뼈 길이의 45%.
- 화살표는 **교본 쪽을 가리킨다**(어느 방향으로 고쳐야 하는지).
- 한 번에 **한 항목만** 그린다. 여러 개를 동시에 그리면 못 읽는다.
- 무대 아래 한 줄 수치: `백스윙 탑 · 42° 교본 24°` — 측정값은 `--amber` 굵게,
  교본은 `--ink-3`.

참조 구현이 저장소에 있다: **`mockups/shell_reference.html` 의 화면 ③** 과
`mockups/target_2d.jpg`. SVG 로 들어 있으니 그대로 가져다 쓰면 된다.

## 과장 크기

현재 2.5배에서 관절이 **6.70px** 움직인다. 눈에 안 보인다.
`exaggerate.js` 의 채널별 `limits` 와 `project()` 의 변형 제한(뼈 길이의 15%)이
원인이다. **제한을 뼈 길이의 40% 까지 올린다.**

| 항목 | 기준 |
|---|---|
| 2.5배에서 최대 관절 이동 | **20px 이상** (390px 폭 캔버스 기준) |
| 1.0배와 2.5배 | 같은 프레임의 두 캔버스 픽셀 차이가 전체의 3% 이상 |
| 교본 잔상 | 과장 자세와 구분되어 보일 것 (스크린샷으로 확인) |
| 부호 | 과장 방향이 측정 방향과 같을 것. 교본을 넘어가 반대로 꺾이지 않을 것 |

# 5단계 — 리포트를 고객 언어로

지금 리포트는 좌표와 내부 지표를 나열한다. 고객이 쓸 수 없다.

## 순서 (위에서부터)

1. **고객이 말한 고민** 한 줄 그대로
2. **그에 대한 답** — 영상에서 확인된 것, 2~3문장. 숫자는 문장 안에
3. **잘한 점** 1~2개
4. **고칠 점** 최대 **3개**. 각각 ⟨국면 스틸컷 + 과장 그림 + 한 줄 수치 + 연습법 한 줄⟩
5. **연습 영상** YouTube 링크 (3번과 4번 항목에 맞춰)
6. 부록 — 전체 수치표. **마지막 페이지**

## 금지

- `추적 신뢰도 0%` 등 내부 지표를 본문에 쓰지 않는다 (부록에만)
- 차이가 **0인 항목을 피드백으로 쓰지 않는다**
- 프레임 번호, 정규화 좌표, 채널 이름을 본문에 쓰지 않는다
- `자기보고의 원인을 영상에서 확정할 수 없습니다` 로 끝내지 않는다.
  확정 못 하면 **무엇이 보였는지**를 쓴다

## 통과 조건
- 본문 1페이지에 1·2번이 들어갈 것
- 고칠 점이 4개 이상이면 심각도 상위 3개만 남길 것
- 본문에 `신뢰도`, `프레임`, `정규화` 문자열이 없을 것 (테스트로 검사)
- 1단계 통과 후 실제 샘플로 만든 PDF 1부를 `mockups/shots/w03_report.pdf` 로 제출

# 제출 규칙

1. 각 단계의 통과 조건 표를 **그대로 복사해 실제 값을 채운다.**
