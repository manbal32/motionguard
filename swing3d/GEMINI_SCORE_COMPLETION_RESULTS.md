# Gemini 숫자 응답 보완

2026-11-20. 캡처에는 설명은 있지만 점수와 타수가 비어 있다. 이전 실제 API 확인에서도 모델이 score_estimate.status=insufficient를 반환했다. 이전 프롬프트가 근거 부족 시 숫자 생략을 명시적으로 허용했던 사실을 확인했다. 사용자 기기의 점수 null 원인까지 재현한 것은 아니다.

변경: Gemini 구조화 응답에 정수 평가점수, 3개 사진 관찰 항목 점수, 가정을 명시한 현재/개선 후 18홀 시뮬레이션 범위가 필수다. 대화에 실제 평균타수가 있으면 자기보고를 반영하고, 없으면 사진/고민에 따른 낮은 신뢰도 추정임을 명시한다. 보통 아마추어 숏게임/퍼팅과 보통 난도의 파72를 가정하도록 요청한다. 숫자 누락·잘못된 범위는 같은 사진5장/승인요약으로 1회 보완 요청한다. 재누락이면502로 재시도 안내, 빈 점수 성공이나 앱의 임의숫자 대체 없음. 두 요청 토큰을 합산하며 score_completion_attempts를 남긴다.

UI 순서: 잘한 점/개선점/연습 → 전체점수 링과 눈금/항목별 막대그래프 → 짧은 설명 → 현재·개선후 타수/시뮬레이션 → 사진·2D 상세. 연습을 수행하지 않았으므로 연습 완료율은 만들지 않는다.

| 확인 | 결과 |
|---|---|
| Node 테스트 | 75/75 통과 |
| 숫자 누락1회→보완 | 같은5장 전달, 실제 모델값 보존 테스트 통과 |
| 2회 모두 숫자누락 | 502, 빈 결과 성공 방지 테스트 통과 |
| 2회 사용량 | 100+100=200 토큰 합산 테스트 통과 |
| UI 순서/항목그래프 | 핵심3줄이 링보다 먼저, 68점과 meter값 보존 테스트 통과 |
| 요약→상세→지도작은골퍼/공 | 회귀 테스트 통과 |
| 실제 iPad/Safari 업로드 전체조작 | 미검증 |

개인 사진/영상/좌표/상담/실제 모델 응답은 공개 Git과 Site 자산에 포함하지 않는다. 사진 평가점수는 계측값이 아니고 타수 범위는 실제 스코어 확정 예측이 아니다.
