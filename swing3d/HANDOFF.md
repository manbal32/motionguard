## 제품 전체의 절대 목표
영상 업로드 → Gemini와 자유 대화(PC Enter/모바일 버튼) → **분석하기 → 대화 핵심 요약 표시·수정·승인** → MediaPipe 계측(33점·9채널·5국면) + 승인 요약을 LLM에 종합 → 수치 근거 있는 잘한 점/문제점 → **동일 프레임 원본 영상과 움직이는 2D 사람형 교육용 과장 비교** → YouTube 연습 링크 → PDF 리포트.

- **과장이 제품의 핵심**. 오른쪽이 머리 없는 스틱 피겨거나, 2.5×에서 변화가 눈에 보이지 않거나, 동작 대신 정지 이미지 한 장이면 미완성.
- **모든 수정은 누적 개선**. 새 불만 한 건만 고치다가 기존 기능을 빼거나 3D/리포트/국면/측정 근거를 퇴행시키지 말 것.
- **과제 MVP의 모든 항목은 이번에 구현**; 장기 목표는 가상 코스·언듈레이션·샷 분포 기반 예상 타수이며 이번 과제 범위 밖이라도 계획에서 삭제하지 않음.

## 2026-11-12 점검 상태 (정적 코드 검토 기준)
- 브랜치: `feature/swing3d`. P0 및 채팅/종합 분석/리포트 구현 커밋은 존재. **기능 체감 품질은 사용자 검토에서 불합격**.
- 현재 코드의 `instrument.js`는 머리/얼굴 렌더링 제외, 가느다란 2D 관절 선만 표시. `mvp_browser.py`는 관절 18점만 확인해 잘못된 시각 테스트를 통과시킴.
- `analyze()`는 상담 요약을 사용자에게 확인시키지 않고 바로 최종 분석. `coach.py`에서도 요약과 최종 판정을 한 번에 호출함.
- 과장 데이터 계산(`exaggerate.js`)은 있지만 `project()`의 변형 제한과 선형 스켈레톤 때문에 **시각적으로 뚜렷한 과장인지 검증 실패**. 정확성을 버리며 임의로 부호/관절을 뒤틀지 말고 아바타/강조/화살표/각도호/구간 반복으로 보완.
- 3D 기능은 이전 코드대로 보존·보조로 이동시키는 방향 유지. 실제 동작은 재검증 필요.
- 이 문서의 상태 서술은 사용자의 로컬 실행 결과가 아니라 GitHub 소스 정적 검토를 바탕으로 함. 구현 후 실제 앱 스크린샷/테스트로 확인한다.

## 역할과 핸드오프
- **사용자**: 제품 방향과 실제 화면 품질 승인
- **검토 AI(ChatGPT 또는 Claude)**: 이 단일 기준을 보존하고 전체 흐름/테스트를 독립 검토하며 Codex에게 통합 작업 지시
- **Codex**: 기존 코드를 수정·테스트하고 Playwright 스크린샷과 커밋 SHA를 제출
- 구현자는 독립 리뷰 대상. 자동테스트 통과만으로 사용자가 화면을 이해할 수 있다고 선언하면 안 됨.

## 환경/보안
- 개발은 개인 Mac(Apple Silicon), 회사 Windows는 읽기 전용. 로컬 MediaPipe 모델과 three.js/GLB 등 벤더 파일은 **유지**해 오프라인 계측이 가능해야 함.
- `.env`, `local-data/`, `.venv/`, `*.mp4`, `*.mov`, `outputs/`, `__pycache__/`는 커밋하지 않는다. Gemini 키는 서버/로컬 환경변수만. 커밋 전 `git diff --cached` 확인.
- 원본 영상은 로컬. 대화 텍스트·계측 요약을 외부 API로 보낼 땐 동의/안내.
- SMPL/SMPL-X/GVHMR의 비영리 라이선스 모델을 사업에 사용하지 않는다.
