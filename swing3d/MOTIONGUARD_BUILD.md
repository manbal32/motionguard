# 0. 이것은 무엇인가

**사업이다.** 과제용 문제정의가 아니다. AI Agent 수업 제출물이기도 하지만,
두 목적이 충돌하면 **사업 쪽을 따른다.**

> 2D·3D 로 고객 중심의 데이터를 제공하고, 문제가 되는 부분을 **조금 과장해서**
> 보여준 뒤 **점수를 매긴다.** 다음에 다시 찍었을 때 개선되면 **누적해서
> 고객의 정보를 관리해 준다.** 향후에는 선수 기준 데이터와 비교해 필드별
> 시뮬레이션으로 **객관적인 예상 타수**까지 간다.

**사람은 12도 차이를 못 본다. 2.5배로 과장하면 본다.**
과장이 제품이고 2D·3D 는 수단이다. 화면에서 차이가 안 보이면 미완성이다.

**다만 "과장"은 우리 내부 용어다.** 고객 화면에는 쓰지 않는다. 고객에게는
**개선 포인트**를 짚어 주고, 그것을 과장해서 보여 주는 것이다.

## 제품의 네 기둥

| | 뜻 | 상태 |
|---|---|---|
| ① 보여준다 | 과장해서 눈에 보이게 | 부분 구현. 2.5배에 6.70px 로 안 보임 |
| ② 매긴다 | 점수로 환산 | **없음** |
| ③ 쌓는다 | 다시 찍으면 비교·누적 | **없음** |
| ④ 환산한다 | 예상 타수 | **없음** |

# 1. 고객이 겪는 흐름

| | 단계 | 고객이 보는 것 |
|---|---|---|
| A | 영상 올리기 | 스윙 한 번. **각도는 아무래도 좋다** |
| B | 상담 | "어디가 고민이세요?" 자유 대화 |
| C | 요약 확인 | 네 칸으로 정리. 고치고 승인 |
| D | 계측 | 진행 표시만. 수치는 보여주지 않는다 |
| E | 촬영 품질 판정 | 못 쓰면 "이렇게 찍어 주세요" |
| F | 결과 | **총점**과 항목 세 개, 이력 |
| G | 개선 포인트 | 교본 잔상 + 과장된 내 자세 + 각도 호. **움직인다** |
| H | 리포트 | 표와 그림, 예상 타수, 연습 영상 |
| I | 저장 | PDF, 그리고 이력에 쌓인다 |
| J | 다시 찍기 | 지난번과 비교 |

구현된 것은 A~D 와 G(약함)뿐이다. E·F·H·I·J 를 이번에 만든다.

# 단계 1 — 얼굴 좌표 제외, 회전은 3D 로

## 1-A. 얼굴 11점을 만들지 않는다

계측에 **쓰이지 않는다.** `swing_track.py` 에 얼굴 랜드마크가 한 번도 나오지 않는다.
아바타 머리도 `pose-avatar.js` 가 목과 몸통에서 계산해 그린다.
영상에 얼굴 점을 찍어 두면 **누구인지만 남는다.**

- `video_pose.py` 의 추출 목록에서 인덱스 0~10 을 뺀다 (어깨 아래 22점만)
- `web/instrument.js` 의 오버레이에서도 뺀다
- 국면 스틸컷에도 얼굴 점을 찍지 않는다

## 1-B. 회전을 3D 좌표로 바꾼다 — 모든 각도에서 잡는다

지금은 어깨가 **얼마나 납작해 보이는지**로 회전을 역산한다
(`acos(어깨폭 / 어깨폭최대)`). 정면에서만 성립하고, 사선·뒤에서는 포기한다.

MediaPipe 는 `pose_world_landmarks` 를 **함께 준다.** 지금 쓰지 않고 있다.
3D 미터 좌표이고 원점이 골반 중심이라 **카메라 위치와 무관하다.**

```python
r = landmarker.detect_for_video(...)
w = r.pose_world_landmarks[0]
ls, rs, lh, rh = w[11], w[12], w[23], w[24]
shoulder = math.degrees(math.atan2(rs.z - ls.z, rs.x - ls.x))
hip      = math.degrees(math.atan2(rh.z - lh.z, rh.x - lh.x))
x_factor = shoulder - hip          # 어깨와 골반의 분리. 골프의 핵심 지표
```

- 어드레스 프레임 값을 0 으로 잡고 상대 각을 쓴다
- ±180° 를 넘는 되돌림(wrap)을 처리한다
- **`camera_facing` 때문에 회전 채널을 포기하지 않는다.** 어느 각도든 잰다
- `x_factor` 를 9채널에 추가한다

**각도 크기가 과하다.** 탑에서 몸통 −139.3° 인데 실제 어깨 회전은 90° 안팎이다.
부호와 패턴은 맞다. lite 모델의 z 가 거칠다. **숫자를 맞추려고 상수를 곱하지 마라.**
heavy 모델을 쓰거나, 절대 회전보다 **X-factor 중심**으로 다루는 쪽을 검토하고
어느 쪽이든 실측값과 함께 보고하라.

# 단계 2 — 국면 검출

## 규칙

```
1. 손 중점(LEFT_WRIST, RIGHT_WRIST) 화면 좌표의 속도를 구한다
2. 평활 창 = fps/12 (홀수)
3. 가장자리 fps×0.07 프레임은 속도를 0 으로 버린다
   ← 첫 프레임에서 속도가 4.89 로 튀는데 나머지는 0.15 이하다.
     이 이상치 하나가 임계값을 잡아먹어 스윙 구간을 f0~f2 로 만든다
4. 임계 = 중앙값 + (95분위 − 중앙값) × 0.35
5. 임계를 넘는 연속 구간. 간격 fps×0.25 이하는 한 구간으로 잇는다
   ← 탑에서 손이 멈추므로 잇지 않으면 백스윙과 다운스윙이 쪼개진다
6. 길이 fps×0.12 미만 구간은 버린다
7. 손 높이 변화가 가장 큰 구간이 본 스윙.
   앞 fps×0.15, 뒤 fps×0.25 만큼 넓힌다
8. 탑     = 구간 안에서 손이 가장 높은 프레임
9. 임팩트 = 탑 + fps×0.05 이후에서 손이 가장 낮은 프레임
10. 다운  = 탑에서 임팩트까지 손이 수직 거리의 50% 를 지난 프레임
    ← 시간의 절반이 아니다. 손은 늦게까지 높이 있다가 한 번에 떨어진다
```

## 임팩트 검증 — 무릎 기준은 틀렸다

**골프 임팩트에서 손은 허벅지 높이다.** 무릎 아래가 아니다.
실측 손 0.513 / 무릎 0.651 이라 멀쩡한 임팩트가 실패로 나왔다.

```
검증: |손 높이(임팩트) − 손 높이(어드레스)| < 0.06
실측 |0.513 − 0.548| = 0.035  → 통과
```

## 임팩트를 못 찾았을 때

**틀린 임팩트를 보여주느니 묶는다.**

| | 메인 프레임 |
|---|---|
| 임팩트 확인됨 | 어드레스 · 탑 · 다운 · **임팩트** · 피니쉬 |
| 확인 실패 | 어드레스 · 탑 · **다운스윙** · 피니쉬 (사진 한 장) |

# 단계 3 — 촬영 품질 안내

**0을 내지 말고 사람 말로 안내한다.**

| 상태 | 조건 | 문구 |
|---|---|---|
| `too_far` | 어깨폭 픽셀 < **60px** | 촬영 거리가 멀어 몸의 회전을 잴 수 없습니다. 몸 전체가 화면 높이의 3분의 2를 채우도록 다시 찍어 주세요. |
| `tracking_failed` | 채택률 < 50% | 영상이 흔들리거나 인물이 가려져 자세를 추적하지 못했습니다. 고정된 위치에서 다시 찍어 주세요. |
| `no_swing` | 스윙 구간 미검출 또는 국면 미확정 | 스윙 한 번이 처음부터 끝까지 담기지 않았습니다. 어드레스부터 피니쉬까지 한 번만 담아 주세요. |

```json
"meta": { "usable": false, "unusable_reason": "too_far", "guidance": "..." }
```

- `usable:false` 면 **LLM 호출 전에** 차단한다
- 화면에 문구 + **"다시 찍기"** 버튼 + 올바른 촬영 예시 그림(SVG, 새로 그린다)
- **촬영 각도는 더 이상 실패 사유가 아니다.** 3D 로 재므로 어느 각도든 잰다

# 단계 4 — 점수

```
편차   = |측정 − 교본|
항목점수 = max(0, 100 − 편차 / 허용폭 × 100)
총점   = 측정된 항목 점수의 가중 평균
```

- `허용폭` 과 가중치는 **`reference.js` 상수**로 분리한다. 나중에 선수 기준으로 교체
- **측정 불가 채널은 제외한다. 0점으로 넣지 마라**
- 신뢰도 0.3 미만 표본은 점수 산출에서 뺀다

```json
"score": { "total": 72,
  "items": [{"channel":"torso","phase":"top","score":76,
             "measured":21,"reference":34,"state":"적정"}],
  "measured_count": 4, "excluded": ["head_sway"] }
```

## 상태는 세 가지

| 상태 | 뜻 | 색 |
|---|---|---|
| **적정** | 기준 범위 안 | 초록 |
| **부족** | 기준에 못 미침 | 주황 |
| **과다** | 기준을 넘어섬 (오버스윙 등) | 주황 |

**색만으로 구분하지 않는다. 글자로도 쓴다.**
**"측정 안 됨" 줄은 화면에 올리지 않는다.** 목록과 총점에서 빼고,
총점 아래에 `이번 영상에서는 네 항목을 쟀습니다` 한 줄을 적는다.
항목이 빠진 회차는 이력 그래프에서 점을 비워 둔다. **점수가 조용히 거짓말하면 안 된다.**

## 통과 조건

| 항목 | 기준 |
|---|---|
| 총점 | 0~100. 값 보고 |
| 측정 불가 | `excluded` 로 가고 총점에 영향 없을 것 (테스트) |
| 재현성 | 같은 입력 두 번 돌려 총점 차이 3점 이내 |

# 단계 8 — 누적과 예상 타수

## 8-A. 누적

- 분석 1건을 `reports/<id>.json` 에 저장하는 기존 경로를 유지하고 **`profile_id`** 를 추가
- 로그인을 만들지 않는다. 브라우저가 UUID 를 만들어 `localStorage` 에 두고 함께 보낸다
- 서버는 `profiles/<profile_id>.json` 에 **요약만** 누적한다

```json
{ "profile_id": "...", "entries": [
  { "report_id": "...", "date": "2026-11-19", "score_total": 72,
    "items": [{"channel":"torso","phase":"top","score":76,"measured":21}],
    "measured_count": 4 } ] }
```

- **영상·좌표 전체는 누적하지 않는다.** 점수와 항목 수치만
- `localStorage` 가 지워지면 새 프로필로 시작하고 **"이전 기록을 찾을 수 없습니다"** 한 줄
- 프로필 삭제 버튼을 둔다
- **촬영 조건이 다르면 비교하지 않는다.** 항목 구성이 다르면 그 항목은 빼고 사유를 적는다

## 8-B. 예상 타수

**LLM 에게 매번 추정시키지 않는다.** 같은 영상에서 다른 답이 나오면 객관적이라 할 수 없다.
**계측값에서 식으로 환산하고, LLM 은 그것을 말로 풀기만 한다.**

```
기준타수 = 상수 (reference.js)
감점     = Σ (항목 가중치 × (100 − 항목점수) / 100 × 항목 타수영향)
예상타수 = 기준타수 + 감점
표시     = 범위로. ±2타
개선시   = 고칠 점 3개가 '적정'이 됐을 때의 재계산값
```

- **범위로 준다.** 단일 숫자는 정확해 보이지만 근거가 없다
- **어떤 수치에서 나왔는지 함께 보여준다**
- 측정하지 못한 항목은 환산에 넣지 않고, **그래서 범위가 넓어졌다고 밝힌다**
- 듣기 좋게 낮추거나 개선 폭을 부풀리지 않는다

### 반드시 함께 쓰는 조건

> **평지가 많은 코스 기준입니다.** 언듈레이션이 심하거나 그린이 까다로운
> 코스에서는 더 나올 수 있습니다. 스윙 계측에서 나온 추정이며 경기 기록이 아닙니다.

이 문구를 빼지 마라. 타수는 스윙만으로 정해지지 않는다. **지키지 못할 약속을 하지 않는다.**

## 8-C. 연습 영상

지금은 영상을 고르는 것이 아니다. `coach.py` 가 검색어를 만들고
`youtube.com/results?search_query=` 로 보낸다. **고객은 검색 결과 페이지를 받는다.**

**`drills.js` 에 직접 고른 목록을 둔다.**

```js
{ channel: "weight_shift", phase: "impact",
  title: "체중 이동 드릴 — 왼발로 밟고 치기",
  videoId: "...", seconds: 252 }
```

- 자주 나오는 결함 10~15개를 덮는다
- 표에 없으면 기존 검색 링크로 떨어진다
- 카드에 **제목 · 길이 · 몇 번 고칠 점인지**를 적는다
- 어떤 영상을 추천하느냐가 코칭 품질이다. LLM 이 매번 지어내게 두지 않는다

## 통과 조건

| 항목 | 기준 |
|---|---|
| 2회 분석 | 같은 `profile_id` 로 두 번 돌리면 두 번째에 비교가 나올 것 |
| 첫 분석 | 비교 영역이 **없을 것** (빈 칸으로 두지 않는다) |
| 저장 내용 | `profiles/*.json` 에 좌표·영상이 없을 것 (테스트) |
| 예상 타수 | 같은 입력 두 번에 **같은 값**이 나올 것 |
| 코스 조건 문구 | 타수 옆에 반드시 있을 것 (테스트) |
| 연습 영상 | 고칠 점 3개에 각각 하나. 표에 없으면 검색 링크 |

### 겹침 — 두 군데가 겹쳐 있었다

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| `보내기`가 `분석하기` 밑에 깔림 | **+61px 겹침** | −40px |

원인은 한 가지다. `.flow-body`가 스크롤 영역인데 그 안의 아래 단추가
`margin-top:auto`로 붙어 있어, 내용이 넘치면 단추 위로 올라탔다.

  에 `background`를 깔아 늘 맨 위에 둔다. 본문이 그 밑으로 지나간다.
- 넘칠 수 있는 영역은 스스로 스크롤한다 — `#coach-log`, `.summary-fields`.
- 요약 칸의 `textarea`는 `height:auto`에 글 길이만큼 늘린다(`fitFields`). 고정 높이로 자르지 않는다.

### 영상은 줄이고 대화를 늘린다

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| 영상 미리보기 | 본문의 **31%** | 22% |
| 대화 목록 | 본문의 **11%** (72px, 바닥값에 붙어 있었다) | 24% (158px) |

- `#upload-preview`는 `height:clamp(110px,18vh,150px)`에 `width:auto`다.
  꽉 채우면 세로 영상이 검은 띠에 둘러싸여 자리만 먹는다. 영상에 상자를 맞춘다.
- 동의에 체크하면 `영상·상담 데이터 안내`는 접힌다. 그 자리는 대화가 가져간다.
- **대화가 주인공이다.** 10-H 가 미리보기를 본문의 30% 이상으로 둔 것은
  빈 화면을 막으려던 것이었다. 기준을 **18%~26%** 로 바꾼다.

### 아바타는 사람 비례로 그린다

측정값은 손대지 않는다. **각도가 판정의 대상이고, 길이는 그림의 문제다.**

- 어깨폭이 `측정/2 + 0.1h` 였다. 어드레스에서 몸통 길이의 **1.42배**가 되어 널빤지였다.
  `clamp(측정/2, 0.17h, 0.45h)`로 바꾼다. 정면이면 0.90h, 측면이면 0.34h다.
- 넓적다리·정강이·위팔·아래팔은 교본 길이(`SEGMENTS`)의 **85%~100%** 안으로 묶는다.
  카메라를 향한 팔다리는 짧게 보이는 것이 옳으므로 교본을 넘겨 늘리지 않는다.
- **발과 손은 손대지 않는다.** 투영에 따라 길이가 크게 변해 널빤지가 된다.
- 이 보정은 `SwingPoseAvatar`(혼자 서 있는 아바타)에만 쓴다.
  **영상 위에 겹치는 골격(`#joints`, `#mobile-pose`)에는 절대 쓰지 않는다.**
  그건 측정한 자리에 그대로 있어야 한다.

### 리포트에 좌표값을 적지 않는다

고객이 `0.177`을 읽고 할 수 있는 일이 없다.

- `shiftX`, `heelR`은 정규화한 비율이다. **교본을 100으로 둔 값**으로 적는다 → `21% / 교본 100%`.
  부호가 반대면 숫자가 아니라 `반대 방향`이라고 적는다.
- 각도는 사람이 아는 단위이므로 `°` 그대로 둔다.
- 결론 문장도 비율 채널에서는 숫자를 빼고 그 동작이 하는 말로 적는다 →
  `피니쉬에서 오른 뒤꿈치가 교본보다 덜 들렸습니다.`

### 사람이 낼 수 없는 값은 측정이 아니다

`몸통 회전 −139.3°`가 고객 표에 찍히고 있었다. 사람은 그렇게 돌지 않는다.

- `reference.js`의 `scoring.plausible`에 채널별 범위를 둔다.
- `scoring.compute`는 그 범위 밖의 값을 **점수에서 빼고 `excluded`에 넣는다.**
- 틀린 수치를 적느니 못 쟀다고 적는다. 이것은 과장이 아니라 계측 실패다.
- 이 거름망은 회전이 과대 추정되는 문제를 **가리지 않는다.** 그 문제는 그대로 남아 있다.

### 점수 하나만 크게 두지 않는다

`31 / 100`만 보고는 좋은지 나쁜지 알 수 없다. 30–50대가 한눈에 읽어야 한다.

- 점수 옆에 말로 된 판정을 붙인다 — `고칠 점이 뚜렷합니다.`
- 그 아래 한 줄로 `이번에 먼저 고칠 것 · 오른 뒤꿈치`를 세운다.

### 말

- 국면 이름은 **피니쉬**로 통일한다. `피니시`로 쓰지 마라.
- 조사는 받침을 보고 고른다(`coach.josa`). `뒤꿈치은`, `뒤꿈치을`은 틀렸다.
