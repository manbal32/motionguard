# MotionGuard 과제 MVP 통합 계획 · 2026-11-12

> **상태: 사용자 요구 확정 / 구현 지시 기준.** 이 문서는 2026-11-12 대화에서 확정한 과제 범위(1~4차)의 최신 제품 요구사항이다. 기존 `CODEX_NEXT.md`의 2D 수정·검증 순서는 유지하되, 이 문서에 적힌 사용자 흐름이 과거 `PRODUCT_FLOW.md`의 "대화 루프 없음"보다 우선한다. **이 문서 자체는 기능 구현 완료의 증거가 아니다.**

## 제품 한 줄

사용자가 골프 스윙 영상을 올리고 AI와 고민을 이야기한 뒤 **분석하기**를 누르면, 대화 내용과 영상에서 직접 얻은 계측 근거를 구분해 LLM이 잘한 점/개선점을 제시한다. 원본 영상과 **교육용 과장 2D 비교**로 문제를 보여주고, 교정 영상 링크와 PDF 리포트까지 전달한다.

## 과제 MVP 화면 흐름

1. **영상 업로드 + 자유 대화**: MP4/MOV 선택. 상담은 자유 입력, 분석 전 반드시 대화가 있을 필요는 없다. 상담 모델은 사용자의 자기진단(예: "어깨 회전 부족")을 사실로 확정하지 않는다.
2. **분석하기**: 버튼을 누르면 (A) 대화에서 사용자가 보고한 증상·목표·자기추정을 요약하고 (B) 기존 `/api/video`로 전 프레임 MediaPipe 33관절 → 9채널 트랙 → 5국면을 추출한다. 둘을 서로 독립된 필드로 보관한다.
3. **LLM 종합 판정**: 측정 수치/신뢰도/교본 차이와 대화 요약을 구조화해 Gemini로 전달한다. LLM은 잘한 점, 개선점(최대 3개), 측정 근거, 불확실성, 연습법을 반환한다. **사용자 주장만으로 실제 결함을 확정하지 않는다.**
4. **2D 비교**: 왼쪽 원본 영상+관절 좌표, 오른쪽 같은 프레임의 2D 뼈대와 교육용 과장. 선택한 결함의 시간 범위·관절·측정/교본/표시값을 보여준다. 1.0배는 측정 자세와 같고, 1.5/2.0/2.5배는 문제 차이를 눈에 띄게 보여주되 부호 반전·비현실적 관절 파손을 금지한다.
5. **교정 영상 + 리포트**: finding별 한국어/영어 YouTube **검색 링크**를 제공(기존 구현 재사용). 기존 리포트 화면에 실제 측정, 상담 내용, 피드백, 과장 이미지, 측정 한계, 링크를 모으고 브라우저 인쇄/PDF 저장을 제공한다.
6. **과제 제출용 시연 경로**: 영상 업로드 → 짧은 자유 대화 → 분석하기 → 근거 있는 판정 → 2D 강조 → 연습 영상 검색 → PDF. 샘플/모의 결과는 화면에 명확히 표시한다.

## 기존 Claude 설계 재사용

- **유지**: `server.py` 업로드/추출·캐시, `video_pose.py`, `swing_track.py`, `reference.js`, `exaggerate.js`, `findings_contract.py`, `findings-ui.js`, `instrument.js`, `report.html/js/css`, 로컬 MediaPipe 모델, 로컬 three.js 및 에셋.
- **화면 방향 유지**: 2D 나란히 비교가 메인, 3D는 접힌 보조 기능. 측정값과 과장값 구분, 어두운 계측 장비 스타일, `mockups/DESIGN.md` 토큰/서체/선 중심. 보라·파랑 계열 일반 AI 챗봇 UI로 바꾸지 않는다.
- **변경**: "대화 루프 없음"을 폐기하고 분석 **전** 자유 상담 추가. LLM은 영상 근거와 대화 맥락의 **합의점과 불일치**를 함께 설명한다. Gemini 우선, 향후 다른 제공자로 교체 가능하도록 어댑터 분리.
- **범위 제외**: 신규 3D 품질 개선, 생성형 동영상으로 실사 변형, 골프 코스/언듈레이션/18홀 타수 예측, 완전한 클럽 추적, 다중 LLM 동시 구현. 차기 단계에서 다룬다.

## 개발 지시 (Codex 순서)

### P0 — 이미 기록된 2D 비교 오류 먼저 수정
- `REVIEW_01.md` 4건 해결: (1) 과장 부호 반전, (2) 왼쪽 관절/교본 누락, (3) 오른쪽 뼈대 형상 및 좌표 정합, (4) 수치·레이아웃·국면 라벨·크롭 문제.
- **주의: `REVIEW_01.md`의 예시 수식은 그대로 복사하지 말 것.** `max(abs(measured), 2)` 최소 여유는 0 근처에서 부호 반전을 다시 유발할 수 있다. 예시의 분기식은 경계에서 불연속도 생긴다. 부호와 연속성을 모두 보장하는 식을 선택하고, 0/극소값/경계/배율 1.0~3.0에서 테스트할 것.
- 추천 접근: 한 채널의 실제값 `m`, 추가 변형 `d = (m-r)*(factor-1)*envelope`. `m*d < 0`인 **0 쪽** 변형은 `m * exp(-abs(d)/abs(m))` (m ≠ 0)로 적용하고, `m == 0`인 경우 0을 유지한다. **0에서 멀어지는** 변형은 `m+d`로 처리하되 채널별 유효 범위 및 인체 관절 구조를 별도로 제한한다. 이 식이 완전한 생체역학 제약은 아니므로 캐릭터 연결·손발·좌표 정합 테스트도 필수.
- 1.0배 검증은 원본 영상의 화소와 오른쪽 격자 배경의 차분이 아니라 **동일 좌표계에서 렌더된 스켈레톤/관절 좌표** 차분으로 측정할 것. 배경이 달라 원본 전체 픽셀 비교는 의미가 없다.
- `CODEX_NEXT.md` 스크린샷 6개 자동 생성 게이트를 유지. 소스 코드 수정 후 시연 화면을 찍어 커밋하고 결함 없이 확인되면 다음으로 간다.

### P1 — 상담 UI
- 기존 `web/index.html` 영상 업로드 바로 아래, 분석 버튼 **위**에 상담 화면 추가. 전체 페이지 이동·새 디자인 시스템 불필요. 채팅 내역은 명시적으로 요약해 사용자 고민/목표/추정으로 구분.
- Gemini 대화 API는 서버 측에서만 호출(`GEMINI_API_KEY` 브라우저 노출 금지). API 키 없음/오류 시 **데모 상담**임을 표시하고 텍스트 입력과 분석은 계속 동작. 원본 영상은 외부로 전송하지 않는다.
- 사용자가 입력한 대화와 추출 수치는 외부 LLM 요청 때 서버로 전송될 수 있음을 안내한다. 원본 영상은 로컬 처리 원칙 유지.

### P2 — 근거 있는 LLM 판정
- 분석 버튼 이후 `video_pose`/트랙 추출이 완료되면 기존 5국면 ±5표본 9채널 요약과 신뢰도, 상담 요약을 LLM에 전달. 현재 `PRODUCT_FLOW.md`의 약 3,000 입력 토큰 상한은 **측정 데이터에 대한 기존 목표**이며, 상담 문맥 추가에 따라 실제 사용량을 기록·재산정할 것.
- 반환 응답은 `findings_contract.py` 호환 finding + 별도 `positives`, `summary`, `limitations` 형태. 기존 계약 필드 변경 금지. 측정값/교본값은 **LLM 자유생성이 아니라 계산된 트랙에서만** 채운다. 측정되지 않은 문제는 텍스트 의견으로만.
- `wrist`/캐스팅은 검지 방향이 샤프트의 검증된 대용값이 아니므로 확정적 샤프트·클럽 헤드 판정 금지. 위험 채널은 근거·신뢰도 충족 시에만 사용.
- 키 없음/429/할당량 초과 시 예시 판정을 사용한다면 **예시·모의 결과**로 표시. 실제 측정값을 예시 판정과 섞어 사용자 분석으로 오인시키지 않는다.

### P3 — 2D 선택 결함 및 교정 연결
- 기존 `findings-ui.js` 및 `exaggerate.js`를 재사용하고, finding 버튼 클릭 시 범위 중앙 seek/채널 강조/배율 severity로 일괄 반영.
- 측정된 차이의 강조가 목적이며 "실제 영상 자체를 생성형 AI로 변형"하지 않는다. 1.0배 ↔ 2.5배 전환 시 대응 프레임 동일성 확인.
- YouTube Data API를 첫 MVP에 새로 붙이지 말고 현재 구현의 **검색 결과 링크** 우선. 검색 링크는 검증된 finding의 한·영 검색어에서 생성.

### P4 — PDF와 통합 시연
- 기존 `report.html`/`report.js` 화면을 재사용. 우선 인쇄 전용 CSS + `window.print()`로 **PDF 저장 가능**하게 한다(모든 브라우저에서 자동으로 PDF 파일을 내려주는 기능과 구분).
- 리포트: 상담 요약(자기보고), 잘한 점(측정근거 있는 것만), 개선점 1~3개, 측정/기준/차이, 강조 프레임, 교정 링크, 불확실성, 다음 연습 목표.
- 데모 상태와 실제 API 분석 상태가 리포트/PDF에서도 구분돼야 한다.

## 명확한 통과 기준

- **기본 흐름**: 실제 영상 1개 → 대화 입력 2회 → 분석하기 1회 → 판정 선택 → 같은 프레임 2D 비교 → YouTube 검색 링크 → 인쇄/PDF 저장.
- **비어 있는 대화**도 분석 가능. **API 키 없는 상태**에서도 좌표 추출/2D 비교/데모 상담/모의 판정과 PDF 시연이 가능하되 모의 결과를 뚜렷이 표시.
- **실제 API 키 있는 상태**에서도 원본 영상이 원격 LLM으로 전송되지 않아야 하며, 사용자 대화/계측 요약 전송 안내가 있어야 한다.
- P0: 9채널의 1.0배 값 전 프레임 일치; 부호 반전 0건; 관절 좌표/골반 중심 정합; 6장 스크린샷에 좌우 뷰 모두 포함.
- P2: 유효 응답/잘못된 응답/429/키 없음 각각 테스트. 측정 근거가 없는 finding이 비교 UI에 들어가지 않는다.
- P4: 리포트의 숫자는 시연 프레임 트랙과 일치. PDF/인쇄 시 2D 비교와 주의 문구가 잘리지 않는다.
- **보고**: 수정 파일, 테스트 명령과 결과, 스크린샷 경로, 실제/모의 데이터 구분, 남은 제한, 커밋 해시.

## 주의: 제품 주장 범위

- 교본은 단일 표준이 아니라 교육용 **참고 기준**이다. 카메라 각도·체형·클럽 특성 때문에 절대적인 골프 정답으로 주장하지 않는다.
- 단일 2D 영상으로 정확한 3D 회전량, 클럽 페이스·스핀, 타수 개선 효과를 확정할 수 없다.
- 장기 목표인 가상 코스 스코어 예측에는 클럽별 탄도·좌우 분포·숏게임·퍼팅 데이터를 별도로 수집하고 모델을 검증해야 한다.
