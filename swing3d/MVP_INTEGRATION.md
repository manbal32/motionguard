## 0-A. 새 사용자 요구 — 잘한 동작과 잘못된 동작을 모두 표현하고 사용자 스탠스를 유지 (2026-11-12)

이 절은 **기존 전체 사용자 여정을 유지한 채 추가하는 요구**다. 결함 과장, AI 대화, 상담 요약 승인, 국면, 3D 보조, 유튜브/PDF 중 어떤 것도 삭제하지 않는다.

1. **잘한 점 + 못한 점 모두 영상에 연결**: LLM의 `positives`와 `findings` 각각에 **국면, 기준 프레임, 채널, 측정 수치, 신뢰도**를 대응시켜 클릭할 수 있게 한다. 잘한 점 선택 시 해당 프레임/부위를 표시하고 ‘유지할 동작’으로 설명하며, **긍정 동작은 과장하지 않는다**. 개선점 선택 시 해당 구간 반복 + 교육용 과장 + 교본 잔상/각도호/화살표를 표시한다. 데이터 근거 없는 칭찬은 클릭 가능한 계측 지적처럼 표시하지 않는다.
2. **원본 스탠스와 자세를 출발점으로 삼는다**: 오른쪽 아바타는 일반적인 교본 모델 자세를 복사한 것이 아니라 **그 사용자의 해당 프레임 2D 랜드마크**를 기반으로 한다. 실제 발 위치·발 사이 폭·앞/뒷다리 배치·골반 위치·어깨 높이·척추 전경사·머리 위치·상하체 비율을 **1.0×에서 유지**한다. 다음 프레임에도 사용자 동작을 따라가며 발이 임의로 미끄러지거나 양 다리가 반대 위치로 바뀌지 않아야 한다.
3. **선택된 문제만 국소적으로 변형**: 과장 2.5×는 ‘사용자 동작 + 선택한 문제의 차이 강조’이지 체형/스탠스/카메라 시점 전체 교체가 아니다. 비선택 채널·관절은 최대한 유지. 필요한 연결 관절만 해부학적으로 부드럽게 조절한다. **원본을 고정한 2D 교본 복제**나 **모든 관절이 동시에 움직이는 임의 보정**은 불가. 관절이 정확히 변형되지 않는 경우 과장 불가능성을 명시하고 각도 호/화살표/차이 마커로 보여준다.
4. **UI 선택**: ‘잘한 점(유지)’과 ‘개선점(교정)’을 별도 그룹으로 제공. 둘 중 하나를 선택하면 가운데 원본과 오른쪽 아바타가 **같은 시각**으로 이동한다. 긍정에는 기본 디자인의 무채색 또는 명확한 ‘유지’ 라벨을 사용하고, 잘못된 동작에만 기존 `--signal` 호박색. 경고 색상과 긍정 의미를 혼동시키지 않는다.
5. **리포트 연결**: 잘한 점 1–3개와 개선점 1–3개를 각각 **측정 근거·선택 프레임 이미지·유지/교정 권고**로 표시. 상담 승인 요약과 진단/측정 근거가 분리되어야 한다.
6. **변화 효과의 양적·시각적 게이트**: 1.0×에서 원본과 아바타 2D 스탠스 앵커(양발·양골반·양어깨)의 좌표 오차를 보고. 2.5×에서 선택 결함의 관절/각도/표현 가이드가 기준과 비교해 얼마나 달라졌는지 수치로 보고. 선택하지 않은 발/골반 등 보존 앵커 변위와 비정상적인 뼈 길이 변화를 정량 검증. ‘스탠스 같아 보임’ 같은 육안 주장만으로 끝내지 않는다.
7. **표현 원칙**: 원본 영상과 2D 인체 윤곽은 가능하지만, 단일 2D 영상으로 사람의 실제 얼굴·가려진 팔/클럽·3차원 자세를 복원했다고 주장하지 않는다. 감지 불가/가림은 신뢰도 하락과 함께 표시하고 원본에 없는 움직임을 사실로 만들어 내지 않는다.

**이 요구를 충족하기 위한 구현 우선순위**: 현재 HEAD의 요약 승인/아바타 변경을 먼저 실행·검증 → 잘한 점/개선점 클릭의 국면 연결 → 1.0× 실측 스탠스 고정 → 선택 문제만 과장(2.5× 차이 가시화) → 유튜브/PDF 및 전체 회귀 테스트. 기존 기능을 되돌리는 작업은 금지한다.

## 0. 제품의 핵심 — 끝까지 지켜야 할 것

**가장 중요한 차별화 요소는 ‘문제점을 눈으로 보이게 하는 교육용 과장’이다.** 채팅, 좌표 계측, LLM 문장, PDF, 유튜브 링크가 단독으로 각각 성공해도 **원본과 과장 동작의 차이를 사용자가 알아볼 수 없다면 핵심 제품은 미완성**이다.

- **실제의 근거**: 사용자 원본 스윙은 왼쪽 영상에 그대로, 관절 추적과 계측 수치를 표시한다.
- **이해할 수 있는 과장**: 오른쪽은 같은 시점/같은 촬영각도/같은 스케일의 **움직이는 2D 사람형 시각화**다. 골퍼를 알아볼 수 있는 머리 윤곽·얼굴 방향(가능할 때만)·목·몸통 실루엣·양팔·손·다리·발이 있어야 한다. 추상적인 막대기 18점만 나열한 스틱 피겨는 불합격.
- **문제 부위를 강조**: 선택된 결함의 실제 구간만 주황색으로 표시한다. **1.0× 원본 동작**, 결함 심각도 기본 1.5/2.0/2.5×, 직접 1.0–3.0×. 원본과 교육용 과장은 동기화된 **재생·일시정지·구간 반복·0.5배속·1프레임 이동**을 지원한다. 정지 사진 한 장만 보여주는 것은 불합격.
- **눈에 띄는 효과**: 과장 배율을 올렸는데 사람 모양/관절 위치에 변화가 육안으로 보이지 않는다면 실패. 인체 연결과 방향 부호를 보존할 수 없어 움직임 과장이 제한되는 경우에는 왜 제한됐는지 표시하고 **각도 호/차이선/화살표/교본 잔상과 구간 확대**로 차이를 드러낸다. 결함을 만들어 내거나 미측정 축을 사실처럼 표시해서는 안 된다.
- **숫자와 시각의 일관성**: 측정값·교본값·차이·과장 표시값의 단위와 기준 프레임을 일치시킨다. 과장은 표현용으로만 적용, 원본 계측 트랙은 변경하지 않는다.
- **신뢰성 한계**: 단일 시점 MediaPipe 2D에서는 깊이 방향 회전, 실제 클럽 샤프트·페이스, 공 스핀, 구질 및 18홀 스코어를 단정할 수 없다. 교본은 여러 체형/촬영 조건을 고려한 교육용 참고값이지 유일한 정답이 아니다.

## 1. 최종 과제용 사용자 여정 — 순서 바꾸지 말 것

### A. 영상 업로드
- MP4/MOV 영상 선택, 최대 크기/시간 안내, 정면·측면 등 촬영 방향 확인. 영상은 로컬에서 처리한다. 기존 `server.py` / `video_pose.py` 사용.
- 미리보기로 원본을 보여주며, 사용자 스윙의 실제 프레임과 오른쪽 시각화가 동기화될 기반을 준비한다.

### B. AI와 자유 대화
- 사용자는 골프 스윙의 고민·증상·목표를 Gemini와 **자유롭게 여러 턴** 이야기한다. 사용자의 주장은 측정 사실이 아닌 ‘자기보고’로 취급한다.
- **PC Enter=전송, Shift+Enter=줄바꿈, 한글 IME 조합 확정 Enter는 전송 금지**. 모바일은 엄지로 누르는 보내기 버튼. 빈 메시지·중복 전송 방지, 응답 로딩/실패 안내, 대화 기록 유지.
- Gemini 먼저 구현하고, 향후 OpenAI 제공자를 붙일 수 있게 서버 어댑터를 유지한다. 실제 API 미연결이면 데모라고 표시.
- 영상 원본을 외부 LLM에 전송하지 않는다. 대화 텍스트와 계측 요약의 외부 전송은 안내/동의 후에만.

### C. 분석하기 → 사용자에게 상담 요약을 **먼저 다시 보여주기**
- 사용자가 **‘분석하기’**를 눌러야 다음 단계가 시작된다.
- 이때 대화 핵심을 `고민 / 연습 목표 / 사용자가 생각한 원인`으로 정리하여 독립된 화면/패널에 보여준다.
- **‘요약 수정’과 ‘이 내용으로 종합 분석’** 두 개의 실제 동작 버튼을 제공한다. 확인 없이 곧바로 최종 LLM 판정하지 않는다.
- 사용자에게 승인받은 요약은 이후 종합 분석 입력·화면 결과·PDF 리포트에 **동일한 값으로 전파**한다. 재요약으로 수정값을 덮어쓰지 않는다. 상담 없이도 이용 가능.
- 키가 없으면 요약을 원문 기반의 로컬/데모 상태로 표시. 데모를 ‘실제 AI 요약’으로 속이지 않는다.

### D. 영상 계측 + LLM 종합 판단
- 기존 **MediaPipe 33개 랜드마크 전 프레임**, 9채널 계측, 5국면(어드레스/백스윙 탑/다운스윙/임팩트/피니시), 크롭, 타임라인/스틸컷을 재사용.
- 승인된 `conversation_summary`와 `measured_evidence`, `reference_data`, `confidence`를 각각 명확히 분리하여 Gemini로 전달. 기존 결함 사전과 `findings_contract.py` 호환 유지.
- **잘한 점**(실측 근거), **못한 점/우선 개선 1–3개**(발생 국면·관절·수치·신뢰도), 사용자 자기진단과 실제 관측의 일치/불일치, 구체적 개선 방법 및 한계를 보여준다.
- 추적이 불안정한 국면에서는 무리하게 결함으로 확정하지 않는다. 손목→검지를 실제 샤프트로 확정해 캐스팅/클럽 페이스를 단언하지 않는다.
- 모델이 정량값을 지어내지 못하도록 서버의 실측값을 기준으로 검증·매핑한다. Gemini 오류/429/키 없음에서 데모 결과를 보이면 명시적으로 구분한다.

### E. **핵심 화면 — 원본과 과장의 동기화된 2D 동작 비교**
- **왼쪽**: 실제 영상 + 실측 관절, 국면과 현재 프레임.
- **오른쪽**: 격자보다 시각적으로 선명한 **2D 골퍼 실루엣/벡터 아바타**, 추정 가능한 머리/얼굴 방향, 몸통, 팔/손, 다리/발, 좌우 가림관계. 사진 속 개인의 얼굴을 복제할 필요 없음. 단순 막대기 뼈대는 불가.
- 결과 첫 화면은 임의 피니시가 아닌 **최우선 개선점의 실제 문제 구간**으로 시작. 문제 카드 클릭 시 시간 이동→주요 관절 강조→심각도 과장 기본값 적용→재생/반복. 사람의 눈으로 문제를 알아볼 수 있도록 방향 화살표/오차 호/기준 잔상/세부 확대를 제공한다.
- 과장 그래픽은 **교육용 강조이며 실측영상이 아님**을 바로 아래와 PDF에 명시한다. 영상/화면에 따라 과장된 아바타가 움직여야 하며, **일부 숫자만 바꾸고 뼈대가 거의 안 움직이면 실패**.
- `REVIEW_01.md`의 부호 반전·좌표 정합 이슈와 `REVIEW_02.md`의 머리/몸통 누락 이슈를 모두 회귀 검증한다.
- 기존 3D는 ‘다른 각도에서 보기’ 접힌 보조 기능으로 보존한다. 3D는 깊이를 **추정한 재구성**임을 밝히고 현재 구현을 삭제하지 않는다.

### F. 교정 가이드 / YouTube / 최종 리포트
- finding마다 연습법, 실제 검색 가능한 한국어/영어 **YouTube 검색 결과 링크**를 제공(유튜브 개별 강의의 정확성 검증과 구분).
- 전체 대화의 승인 요약·잘한 점·핵심 개선점과 데이터·원본+과장 비교 캡처·연습 영상 링크·한계·다음 연습 목표를 기존 `report.html/js/css`에 반영. **인쇄→PDF 저장**을 실제 지원.
- 리포트는 원래 `mockups/02_report.html`처럼 종이형 가독성을 지키고, **'재지 못한 것'** 및 여러 문제의 **우선순위/연쇄 관계**를 포함한다. 도구 화면과 리포트 디자인은 별도다.

## 3. 현재 코드에서 발견된 문제 (2026-11-12 정적 점검)

아래는 파일을 읽어서 확인한 사실이며, 로컬 실행 재현/수치 측정 완료를 뜻하지 않는다.

1. `web/instrument.js`의 `FACE_LANDMARKS`가 11개 얼굴 랜드마크를 제외하고 `links`에 머리 연결이 없다. `paint()`는 얇은 선·점 위주라 **오른쪽이 스틱 피겨**다. `tests/mvp_browser.py`가 **18개 점만 존재**함을 기대해 이 퇴행을 오히려 테스트로 굳혔다.
2. `instrument.js analyze()`는 `/api/video`에 이어 곧바로 `/api/coaching/analyze`를 요청한다. `coach.py analyze()`에서 대화 요약과 종합 판정이 한 번에 실행되어 **사용자 확인·수정 기회가 없다.**
3. `web/exaggerate.js`는 측정값 기반으로 차이를 증폭하나, 화면의 `instrument.js project()`는 채널별 회전을 **최대 30°로 제한**하고 몸통 연결을 **최대 15% 상대 변위로 제한하는 로직**이 있다. 화면상 과장이 충분히 보이지 않는 원인 후보이며, **실측→채널→2D 관절 위치의 각 단계에서 실제 변위와 눈에 띄는 정도를 수치/화면으로 검증**해야 한다. 정확성 때문에 제한된 것을 무작정 풀어 관절을 망가뜨리면 안 된다.
4. 결과 렌더링 `setupFindings()`는 3D 뷰어를 즉시 mount한다. 원래 Claude의 `CODEX_NEXT.md`에 적힌 **접힌 3D 보조/지연 로딩**과 다르다. 3D 코드 삭제 없이 점진 개선한다.
5. `mockups/README.md`는 리포트의 “재지 못한 것”과 **세 결함의 연쇄적 설명**을 보존하도록 명시한다. 최종 PDF에 이 두 항목이 실제 들어가는지 검증할 것.

## 4. 종합 완료 게이트 — 각 단계 통과+사용자 눈 검증

**채팅·분석·비교·영상·보고서 전체를 단일 실제 영상으로 시연**한다. 각 화면을 Playwright로 캡처하고 **사람이 읽을 수 있는 크기**로 제출한다.

1. **상담 화면**: PC Enter 전송, 모바일 보내기 버튼, 두 턴 이상 실제/데모 상태 명시. 키 있는 실제 Gemini 경로는 별도 검증.
2. **요약 확인 화면**: ‘분석하기’ 직후 나타나고 고민·목표·추정 세 필드가 채워짐. 수정/승인 전에는 최종 판정 요청이 0회. 수정 후 최종 API 페이로드와 PDF에 동일 값.
3. **판정 화면**: 실측 근거가 있는 잘한 점/개선점 최대 3개/연쇄 원인 또는 불확실성 설명/국면 신뢰도. 결함 카드 클릭이 실제 프레임으로 이동.
4. **2D 핵심 비교**: 머리·목·몸통·손발이 **시각적으로 확인**. 선택된 결함의 실제 프레임 전후에서 좌/우 **동시 애니메이션과 반복 재생**. 1.0배 관절 좌표 정합, 2.0/2.5배에서 변화가 사용자 눈에 확인. 고정된 그림 한 장은 불가. 차이가 작은 경우 수치와 각도호/오차선으로 설명. 프레임 3개 이상 캡처.
5. **우선순위**: 문제를 선택하면 사용자 영상과 과장 화면 **둘 다** 해당 구간의 같은 타임스탬프. 숫자/호/잔상이 해당 finding을 설명.
6. **추천**: YouTube 검색 링크가 실제 열리는 구조이고 근거 없는 임의 추천을 하지 않음.
7. **PDF**: 브라우저 저장 가능한 인쇄 레이아웃, 개인 고민 요약·잘한 점·문제 수치·시각화 이미지·연습법·한계 및 ‘재지 못한 것’ 포함. 페이지 잘림 방지.
8. **회귀 검사**: 기존 3D 뷰어/모델, 9채널/5국면/다운로드, 브라우저/모바일, 데모 경로 유지.
9. **운영**: 키/원본 영상/비공개 파일 커밋 금지, API 사용량 및 실패 원인 구분. 실제 샘플/데모/모의 결과 명시.
10. **시각 판정 필수**: 자동 테스트가 통과해도 오른쪽 화면이 막대기뿐이거나 변화가 식별되지 않거나 요약 승인 단계가 없다면 **완료 처리 금지**.

**사용자가 직접 볼 산출물**: 시연 스크린샷(대화, 확인 요약, 판정, 결함 선택, 1.0×, 2.5×의 실제 동작 3프레임, 모바일, 리포트/PDF), 동작 테스트 기록, 기존 대비 달라진 점, 커밋 SHA.

## 5. 역할·문서 관리

- 사용자 = 제품 방향과 화면 승인, 검토 AI = **전체 목표와 회귀 기준을 관리하며 문제 진단/구현 지시**, Codex = **구현/테스트/스크린샷**. Codex의 구현 결과를 검토 AI가 완성으로 대신 선언하지 않는다.
- 이 파일 **단일 기준**. `HANDOFF.md`는 여기로 연결되는 인덱스. `CODEX_MVP_RUN.md`는 실행용, `REVIEW_01.md`/`REVIEW_02.md`는 발견된 결함 기록. 이전 지시 중 “대화 루프 없음”, “P0만 하고 멈춤”, “Gemini 연결하지 말 것”, “머리 없는 스켈레톤도 통과” 등은 현재 요구를 대체할 수 없다.
- 새 요구/수정이 들어오면 **현재 전체 기능 체크리스트에서 유지/추가/변경을 명시**하고, 누락이나 삭제가 없는지 확인한 다음 Codex 지시서를 갱신한다. 코드를 고치기 전에 기준을 고정하고, 완료 뒤에는 시각 회귀 결과로 다음 라운드를 결정한다.

## 0-B. 고객이 받는 것과 내부 데이터를 분리한다 (2026-11-14)

**좌표와 채널은 제품을 만드는 재료이지 고객에게 주는 결과물이 아니다.**
계측은 그대로 유지하되, 고객이 보는 화면과 리포트는 고객의 언어로 쓴다.

### 고객에게 내보내지 않는 것

다음은 내부 지표다. 화면 본문과 리포트 본문에 그대로 노출하지 않는다.

- 채널 이름 (`torso` `hips` `shiftX` `heelR` …)
- 프레임 번호, 정규 시간, 트랙 인덱스
- **추적 신뢰도 백분율.** `추적 신뢰도 0% · 낮음` 같은 표기는 고객에게 의미가 없고
  제품을 믿을 수 없게 만든다. 신뢰도가 낮으면 **그 항목을 결과에서 빼고**,
  대신 한 줄로 안내한다 — "이 구간은 흔들림이 있어 이번에는 판단을 미뤘습니다.
  측면에서 다시 찍어 주시면 볼 수 있습니다."
- **차이가 없는 항목.** `어드레스 · 몸통 0.0° / 교본 0.0°` 는 피드백이 아니다.
  의미 있는 차이가 있는 항목만 낸다.

### 고객의 언어로 바꾼다

| 내부 | 고객에게 |
|---|---|
| `torso` | 어깨 회전 · 상체가 감기는 정도 |
| `hips` | 골반 회전 |
| `lean` | 상체 숙임 |
| `wrist` | 손목 코킹 |
| `shiftX` | 체중 이동 |
| `top` / `impact` | 백스윙 맨 위 / 공을 맞히는 순간 |
| `-29.9°` | 교본보다 많이 덜 돌았습니다 |

### 리포트 순서 — 이 순서를 지킨다

1. **당신이 물어본 것** — 승인한 상담 요약 그대로
2. **답** — 말로 쓴 설명. 첫 줄은 **자기진단과 실제 관측의 일치 / 불일치**다.
   "골반이라고 보셨는데 실제로는 어깨 쪽이 더 컸습니다" 처럼 쓴다.
   고객이 물어본 증상(슬라이스 등)에 대한 답이 반드시 들어간다.
3. **근거 한 장** — 문제 구간의 원본과 교육용 과장을 나란히 담은 캡처
4. **다른 각도** — 3D 재구성 스틸 한 장. 깊이는 추정이라고 명시
5. **이렇게 연습하세요** — 개선점별 YouTube 링크
6. **재지 못한 것**
7. **부록 · 측정값** — 숫자 표는 **여기서 처음** 나온다

### 화면에서도 같다

비교 화면의 수치 줄(측정 · 교본 · 차이 · 과장 표시)은 유지하되, 판정 카드의
본문은 말로 쓴다. 숫자 근거는 `근거 보기` 로 접어 둔다.
숫자를 없애지 마라 — 이 제품의 신뢰는 측정에서 나온다. 앞세우지 않을 뿐이다.

### 이 절의 전제

신뢰도가 0 이고 과장이 0.6° 인 상태에서는 어떤 문장을 써도 할 말이 없다.
**`CODEX_RUN_04.md` 의 좌표계 수정과 신뢰도 문제가 먼저다.** 이 절은 그 다음 라운드다.

## 0-C. 어떤 촬영 각도든 쓸 만한 답을 낸다 (2026-11-14)

카메라 한 대로는 각도마다 잴 수 있는 것이 다르다. 모든 각도에서 모든 것을 재는 것은
불가능하지만, **각도를 판별해 그 각도가 잴 수 있는 것을 재는 것**은 가능하다.
사용자에게 "다시 찍어 오세요" 를 기본 답으로 삼지 않는다.

### 각도별로 잴 수 있는 것

| 채널 | 정면 | 측면 · 뒤 |
|---|---|---|
| `torso` `hips` 회전 | 가능 | **불가** (어깨 폭이 거의 변하지 않음) |
| `shiftX` 체중 이동 | 가능 | 제한 |
| `lean` 상체 숙임 | 제한 | **가능** (측면이 더 정확) |
| `wrist` 손목 코킹 · 캐스팅 | 제한 | **가능** |
| `kneeL` `kneeR` | 가능 | 가능 |
| `heelR` | 가능 | 가능 |
| `swing` 손 궤도 | 가능 | 가능 |

결함 사전 8종 중 **캐스팅 · 상체 들림 · 무릎 펴짐 · 체중 미이동**은 측면에서 더 잘 보인다.
측면 영상이라고 판정할 것이 없는 것이 아니다.

### 요구

1. 트랙 `meta` 의 추정 촬영 각도에 따라 **판정 가능한 채널 집합**을 정한다.
2. 그 집합 안에서 결함을 판정한다. 집합 밖 채널은 findings 를 만들지 않는다.
3. 결과 화면과 리포트는 **이 각도에서 본 것**을 먼저 보여주고, 그 다음에
   "이것까지 보시려면 정면에서 한 번 더 찍어 주세요" 를 **보조로** 안내한다.
   못 본 것을 앞세워 사용자를 돌려보내지 않는다.
4. 두 각도의 영상을 모두 올린 경우 한 리포트에 합칠 수 있게 설계를 열어 둔다.
   (이번 과제 범위 밖)

### 순서

`CODEX_RUN_05.md` 의 "측정 불가 표시" 가 먼저다. 0 을 내보내지 않게 된 다음,
이 절의 각도별 판정으로 넘어간다.
