# 분석 실패: 응답 형식과 한도 구분

2026-11-20. 사용자 Safari 캡처의 문구는 사진 분석 응답의 필수 항목을 확인하지 못했습니다. 이는 기존 API가 validateVisual의 format 예외에 반환하던 문구다. 키 소진으로 단정하면 안 된다.

- 최근Safari /api/coaching/visual 요청2건이 서버에 도착했고 HTTP502, 약7.35초/7.96초로 종료된 기록을 확인했다. 이전로그에는 구체적거절필드가없다.
- 같은키/설정의 별도 실제5장 확인은HTTP200/12.13초, 사진5장요청ID/해시/전달5개일치. 이 성공은 사용자실패요청 자체를재현한것은아니고 지속적전체차단이아님을보여준다. 당시 분당한도 여부는 이 성공만으로 판단하지 않는다.
- 원래schema region/kind/status가일반STRING이었다. 모델이비허용값을쓰면앱검사에서즉시전체거절됐고 숫자보완보다앞에서종료됐다. 정확한실패필드는원응답을수집하지않아미확정.

## 수정

1. 모델schema의region/kind/status를허용enum으로강제한다.
2. 형식검사/JSON오류/MAX_TOKENS·빈응답도숫자누락처럼같은사진5장/승인요약으로1회보완한다. 실제사용량합산,무한재시도없음.
3. 재실패시request_id/error_code/field명만기록한다. 개인영상/사진/대화/키/모델원문을로그에남기지않는다.
4. upstream429는HTTP429로보존하고quotaMetric이있으면분당/일일구분,대기시간을반환한다. 한도와응답형식오류를같은문구로뭉개지않는다.
5. 클라이언트에확인번호와기기내오류코드를남긴다. 이전대화/요약/리포트·PDF는유지한다.
