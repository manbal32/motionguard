# 3차 검토 · 과장이 화면에서 0이 되는 이유

검토 대상 `0c62307` · 실제 실행(`tests/shots.py`) 후 화면과 수치로 확인함.

---

## 결론

**과장 계산은 정상이다. 화면이 과장을 보여주지 못하는 것이고, 원인은 내(Claude) 지시서의
설계 결함이다.** 국면과 결함 구간이 서로 다른 좌표계에 있어서 어긋난다.

Codex 구현을 탓할 것이 아니다. `findings` 계약을 그렇게 쓰라고 한 것이 나다.

---

## 1 · 증거

### 화면

`mockups/shots/05_top.png` — 백스윙 탑, 과장 배율 **2.5×**:

```
몸통 회전   측정 9.8°   교본 44.0°   차이 -34.2°   과장 표시 9.8°
```

**과장 표시가 측정값과 같다.** 34도나 벗어났는데 2.5배를 걸어도 화면이 움직이지 않는다.
사용자가 "맘에 안 든다"고 한 것의 정체가 이것이다.

### 계산

`web/exaggerate.js`를 트랙과 함께 단독 실행하면 정상이다.

| 배율 | 과장 표시 | 측정 대비 변화 |
|---|---|---|
| 1.0× | 31.57° | 0.00° |
| 1.5× | 25.93° | −5.64° |
| 2.0× | 21.30° | −10.27° |
| 2.5× | 17.49° | **−14.08°** |
| 3.0× | 14.36° | −17.21° |

1.0×에서 측정값과 정확히 일치하고, 2.5×에서 14도가 움직인다. **계산은 요구대로 동작한다.**

## 2 · 원인 — 두 개의 좌표계

| 무엇 | 단위 | 어디서 | 코드 |
|---|---|---|---|
| 국면 | **원본 프레임 번호** | `phase_frames` (검출) | `instrument.js:718` |
| 결함 구간 | **정규 시간 0–1** | `findings[].range` (판정) | `instrument.js:533` |

이 둘은 **독립적으로 계산되고 서로를 모른다.**

- 사용자가 `백스윙 탑` 버튼을 누르면 `phase_frames.top` 프레임으로 점프한다.
- `exaggerate.js`는 그 프레임의 정규 시간이 `range` 안에 있을 때만 envelope 을 세운다.
- 탑이 `range` 밖이면 `envelope = 0` → `extra = 0` → **과장 표시 = 측정값.**

`samples/golf1_export.csv` 기준으로 탑은 정규시간 `0.5803`, 고정 구간은 `[0.52, 0.64]`
이므로 간신히 들어온다. 영상 업로드 경로는 국면 검출 결과가 달라 **밖으로 나간다.**
05_top.png 이 바로 그 경우다.

즉 **결함을 선택하면 보이고, 국면 버튼을 누르면 사라진다.** 그런데 몸통 회전 결함을
보고 싶은 프레임이 바로 백스윙 탑이다. 사용자는 가장 보고 싶은 자리에서 아무 일도
일어나지 않는 것을 본다.

### 고칠 것

**`range`를 정규 시간으로 두지 말고 국면에 앵커링한다.**

```json
{ "channel": "torso", "phase": "top", "span_frames": 8 }
```

구간은 `phase_frames[phase] ± span_frames`로 런타임에 계산한다. 국면 검출이 어디로
움직이든 결함 구간이 따라간다. 기존 `range`는 호환을 위해 읽되, `phase`가 있으면 그것을 쓴다.

**완료 기준** — 국면 버튼 5개를 차례로 누르면서 각 프레임의 `과장 표시 − 측정`을 출력하라.
해당 결함의 국면에서 2.5× 기준 **최소 8° 이상** 벌어져야 한다. 숫자로 보고하라.

## 3 · 더 깊은 문제 — 회전의 종류가 다르다

이것은 1번을 고친 뒤에도 남는다. **1번보다 먼저 손대지 마라.**

`torso` · `hips` · `lean`은 **폭·길이 단축률에서 역산한 값**이다.

```python
turn = acos(shoulder_width / shoulder_width_max) - base   # swing_track.py:274
```

이것은 **화면 밖으로의 회전**(몸통 yaw, 전방 기울기)이다. 2D 화면에서 이 회전의
신호는 **어깨선이 짧아지는 것**이지 기울어지는 것이 아니다.

그런데 `project()`는 이것을 **화면 안 회전**으로 적용한다.

```js
turnTorso(upper, shoulders, delta("torso"), [[11,23],[12,24]]);   // instrument.js:443
// rotate(indices, pivot, angle) — 이미지 좌표에서 점들을 회전
```

상체 전체(인덱스 0–22)를 어깨 중심으로 18.6° 돌린다. 화면에서 이것은
**"몸이 옆으로 기울었다"**로 보인다. **"몸통이 덜 돌았다"로는 보이지 않는다.**
자유도가 다른 축에 값을 넣고 있다.

### 고칠 방향 (확정하기 전에 보고할 것)

yaw 과장의 2D 표현은 **회전이 아니라 폭 변화**다.

- `torso` → 어깨선 좌우 거리를 `cos` 비율로 줄이거나 늘린다. 어깨 두 점을 어깨 중심에서
  멀어지거나 가까워지게 옮기고, 팔은 그 어깨에 따라붙인다.
- `hips` → 골반 두 점에 같은 방식.
- `lean` → 골반–어깨 세로 거리의 단축률. 세로 길이를 조절한다.

이렇게 하면 "덜 돌았다"가 **어깨가 정면을 향한 채 넓게 남아 있는 모습**으로 나온다.
실제로 그렇게 보이는지는 구현 후 스크린샷으로 확인해야 한다. 지금은 가설이다.

**각도 호 · 차이 화살표 · 교본 잔상**을 함께 쓰라는 `MVP_INTEGRATION.md` 0-A 3항의
지시가 여기에 걸린다. 관절 변형만으로 yaw 를 보여주기 어려우면 **보조 표시로 드러내고,
왜 제한됐는지 화면에 적는다.** 자세를 임의로 비틀지 마라.

## 4 · 작은 것들

- **클럽이 없다.** 오른쪽 아바타에 샤프트가 그려지지 않는다. 골프 스윙 시각화인데
  클럽이 없으면 무엇을 하는 자세인지 읽히지 않는다. 손목→검지 방향으로 샤프트를 그린다.
- **`잘한 점 · 유지`가 비어 있다** — `findings/golf1.json`에 `positives`가 **0개**다.
  `findings-ui.js`와 `coach.py`는 둘 다 `positives`를 처리한다. **코드가 아니라
  고정 데이터의 공백**이다. 픽스처에 측정 근거가 있는 긍정 항목 2개를 넣어라.
- **`검증용 · 골반 회전` 카드**는 `tests/shots.py:89`가 주입한 것이다. 제품 버그가 아니다.
  다만 스크린샷이 제품 화면으로 보이므로 테스트 주입 항목에는 접두어를 붙여 구분하라.
- **`hips`가 백스윙 탑에서 `0.00°`** — `swing_track.py:275`의 `max(0.0, …)` 클램프다.
  **내가 넣은 것이고 내가 본다. 손대지 마라.** 이 때문에 골반 결함은 지금 판정 자체가 안 된다.

## 5 · 지시 체계가 너무 크다

지시 문서가 **14개 파일 1,607줄**이고, 그중 몇 개는 본문에 "이전 흐름은 무효",
"P0에서 멈추기는 무효"라고 적힌 채 남아 있다.

```
WORK_ORDER 270 · CODEX_TASK 291 · CODEX_NEXT 228 · MVP_INTEGRATION 118
PRODUCT_FLOW 115 · REVIEW_01 101 · CODEX_MVP_RUN 81 · REVIEW_02 69 · HANDOFF 41 …
```

부분 무효 문서를 읽는 구현자는 무엇이 살아 있는지 매번 추측한다. 추측이 쌓이면
오늘 같은 결과가 나온다.

**정리 제안** — 정본 `MVP_INTEGRATION.md` 하나와 최신 리뷰 하나만 `swing3d/` 에 두고,
나머지(`CODEX_TASK.md` · `CODEX_NEXT.md` · `WORK_ORDER.md` · `PRODUCT_FLOW.md` ·
`REVIEW_01.md` · `REVIEW_02.md` · `CODEX_MVP_RUN.md`)는 `swing3d/archive/` 로 옮긴다.
삭제하지 않는다. 이력은 남기되 읽는 경로에서 뺀다. `HANDOFF.md` 의 표에서도 지운다.
