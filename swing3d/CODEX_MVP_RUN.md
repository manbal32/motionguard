## 1. 사용자 경험 — 실제 AI 자유 대화 (반드시 구현)

1. 영상 업로드 후 **AI 골프 코치와 자유롭게 대화**할 수 있도록 UI를 영상 입력 곁에 추가한다. 대화는 분석 전 자유롭게 여러 턴 가능하고, 메시지를 보내면 실제 LLM 호출로 응답한다. 고정 문장만 반환하는 '가짜 채팅'은 이 단계 완료로 인정하지 않는다.
2. 기본 모델 제공자는 **Gemini**. 대화와 최종 판정을 서버 측 API로 구현하고, 제공자별 호출 로직은 어댑터로 분리해 향후 OpenAI 모델을 추가할 수 있게 한다. **이번 MVP에서 OpenAI 제공자까지 반드시 구현할 필요는 없다.**
3. API 키는 `GEMINI_API_KEY` 환경 변수 또는 무시되는 로컬 `.env`에서만 읽고, 브라우저 JS·HTML·로그·Git 커밋에 포함하지 않는다.
4. 대화 목적은 증상/불편/목표/사용자 추정을 수집하는 것. '내가 슬라이스가 나니 골반 회전이 부족하다'는 진술을 **관측 사실로 확정하지 마라**. 분석 전에는 아직 확인되지 않았다고 말할 수 있어야 한다.
5. 키가 없거나 호출 실패 시 일반 입력 UI는 유지하되 '데모 응답' 또는 '오프라인 예시'를 **눈에 띄게 표시**한다. 사용자에게 실제 LLM 답변이라고 속이면 안 된다.
6. 이 단계에서 **원본 영상 파일은 LLM API에 보내지 않는다**. 대화 텍스트 및 최종 수치 요약이 외부 API로 전송된다는 사실은 UI에서 안내한다. 로컬 오프라인 분석과 외부 모델 호출을 구분한다.

### 필수 채팅 입력 UX — PC Enter 전송 / 모바일 보내기 버튼

- **데스크톱(PC)**: 대화 입력창에서 `Enter`를 누르면 즉시 메시지를 전송하고 AI 응답을 받는다. **`Shift+Enter`는 줄바꿈**이며 전송하지 않는다. 키보드 전송이 기본 동작이므로 보내기 버튼을 누르도록 강요하지 않는다.
- **한글·일본어 등 IME 입력 중** `Enter`로 글자/조합을 확정하는 순간에는 전송하지 않는다. 이벤트의 `isComposing`, `keyCode === 229` 및 조합 시작/종료 상태를 고려하라. 특히 macOS·Windows 한글 입력 둘 다 검증한다.
- **모바일**: 입력창 옆에 엄지로 누르기 쉬운 **보내기 버튼**을 표시한다. 터치로 전송할 수 있어야 한다. 모바일 키보드의 전송 액션을 지원해도 되지만, 터치 버튼을 없애지는 마라.
- **공통**: 보내기 버튼도 키보드/스크린리더 접근을 위해 유지하되, PC의 기본 전송은 Enter다. 빈 문자열(공백만 포함)은 전송하지 않는다. 보낸 즉시 사용자 말풍선을 표시하고, AI 답변 중 로딩/오류/재시도 상태를 보여준다. 대화가 길어지면 최신 메시지가 보이게 스크롤하며, 한 번의 Enter나 클릭으로 요청이 중복 전송되지 않도록 한다. 완료 후 입력 포커스를 유지하여 다음 말을 곧바로 입력할 수 있게 한다.
- **중요한 구분**: Enter 또는 보내기 버튼은 **채팅 메시지 전송**일 뿐이다. 최종 영상/대화 종합 판정은 별도의 **'분석하기' 버튼**을 눌렀을 때만 시작한다. 채팅마다 영상 분석을 다시 실행하지 않는다.
- **필수 테스트**: 데스크톱 Enter 전송, Shift+Enter 줄바꿈, 한글 조합 확정 Enter 전송 방지, 빈 메시지 방지, 모바일 390px 보내기 버튼의 가시성·클릭, 중복 전송 방지, 다중 턴 후 '분석하기' 시 대화 기록 반영을 테스트한다.

## 2. '분석하기' 단일 버튼 — 대화 + 영상 결합

- 버튼 누르기 전에는 최종 판정이 실행되지 않는다.
- 클릭 시 (a) 실제 대화 이력에서 고민/목표/자기 진단의 **대화 요약**, (b) 기존 `/api/video` 경로의 전 프레임 MediaPipe 좌표/9개 채널/5국면 + 신뢰도 요약을 확보한다.
- 두 데이터는 서버에서 **서로 다른 명시 필드**로 LLM 프롬프트에 합친다. 예: `conversation_summary`, `measured_evidence`, `reference_data`, `confidence`. 사용자의 의견으로 측정값을 덮어쓰지 않는다.
- LLM은 **잘한 점, 개선할 점(최대 3개), 숫자로 된 근거, 추정/불확실성, 연습 가이드**를 반환한다. `findings_contract.py`와 기존 findings 구조를 재사용·확장 호환한다. 잘한 점도 관측 근거가 없으면 '확인 불가'로 표현한다.
- **수치를 LLM이 지어내지 않도록** 서버에서 허용 채널·구간·실제/교본 수치를 계산해 응답에 매핑/검증한다. 근거 없는 지적은 텍스트로만 표시하며 2D 과장 버튼을 생성하지 않는다.
- 영상 촬영 각도·가림·신뢰도 부족의 한계를 표시한다. 단일 2D 영상만으로 볼 구질, 스핀, 정확한 3D 회전량이나 클럽페이스를 확정하지 않는다.
- API 오류/429/키 없음은 자동화 테스트로 확인. 예시 판정을 보여주면 **예시 데이터**라고 표시하고, 사용자 영상에서 실측한 결과인 것처럼 혼합하지 않는다.

## 3. 2D 비교 — 대화 기반 판정 결과와 반드시 연결

- 왼쪽: 원본 영상+실측 관절 좌표. 오른쪽: 같은 시점의 2D 교육용 과장 뼈대. 기존 코드 재사용.
- LLM findings 중 **유효한 결함 선택** → 해당 프레임으로 자동 seek → 해당 관절 강조 → 심각도에 맞는 과장 배율 기본 적용(1.5, 2.0, 2.5).
- 배율 1.0에서는 원본의 관절 좌표와 오른쪽 뼈대 좌표가 일치. 배율은 1~3. 실제 측정값, 교본값, 과장 표시값을 명확하게 분리. **과장 그래픽이 실측 결과 아님**을 모든 화면/리포트에 표시한다.
- 기존 P0 테스트와 스크린샷 6장을 회귀 테스트로 실행하여 결함 재발 방지. 도형 연결/부호·영역 무결성 확인.
- 3D 뷰어는 삭제하지 않고 보조로 유지. 과제 우선 범위에서 신규 3D 개선은 하지 않는다.

## 4. 교정 영상 + 최종 PDF 보고서

- 각 유효한 개선 항목에서 한·영 검색어로 **실제 열리는 YouTube 검색 결과 링크**를 제공. 기존 `findings-ui.js` 활용. YouTube Data API를 과제 MVP 필수로 강제하지 않는다. 검색 결과를 '검증된 강의 영상 추천'이라고 과장하지 마라.
- 기존 `report.html`, `report.js`, `report.css`를 확장한다. 보고서에 ① 사용자 상담 요약(자기보고), ② 분석 영상/촬영조건과 측정 한계, ③ 근거 있는 잘한 점, ④ 최대 3개 개선점 및 각도/구간, ⑤ 실제/교본·교육용 과장 이미지, ⑥ 교정 연습과 YouTube 링크, ⑦ 다음 촬영/연습 목표를 담는다.
- **브라우저 인쇄 → PDF 저장**을 실제 구현하고 프린트 CSS를 테스트한다. 별도의 PDF 생성 서버를 추가하지 않아도 된다. 사용자가 바로 저장 가능한 UI 버튼과 안내가 있어야 한다.
- 예시/데모 데이터는 인쇄된 보고서에도 '예시'라고 표시한다.

## 5. 완료 기준과 필수 검증

1. 실제 MP4/MOV 업로드 → 사용자 메시지 **2회 이상** → 각 메시지에 대해 대화형 AI 응답 (키 설정 시 실제 Gemini API).
2. 분석하기 클릭 → 대화 요약 생성 + 영상 관절 측정 → 이를 함께 사용한 종합 피드백. 상담 내용과 근거가 일치하지 않으면 불일치도 설명.
3. 개선 항목 클릭 → 해당 시간 범위로 이동 → 2D 실제/교육용 과장 동기화, 배율 변경 확인.
4. 개선 항목별 YouTube 검색 링크가 열리고, 보고서에 1~3의 정보가 반영됨.
5. 인쇄 버튼으로 인쇄/PDF 저장 화면에 진입하고, 스크린샷/헤더/수치/주의문구가 잘리지 않는지 확인.
6. API 키 없음 시 **데모 모드**로 시연 가능하며 모든 모의 결과를 명확히 구분. 실제 API 키 있을 때의 동작은 키를 공개하지 않고 검증.
7. 자동 테스트: 기존 회귀 테스트, 상담 다중 턴, 빈 대화, 정상/오류/429/잘못된 LLM JSON, 입력 길이 제한, 임의 문자열 주입, 토큰 사용량/오류 표시를 확인.
8. 데스크톱과 390px 모바일에서 **업로드+대화+비교+보고서가 같은 흐름**으로 작동하는 화면을 Playwright로 캡처. 기존 6장 외에 이번 새 UI의 상담/분석/최종 보고서 화면도 추가 캡처.
9. 사용자가 직접 따라할 수 있는 **로컬 실행 명령**, 환경변수 설정 방법(값 노출 금지), 시연 순서, 테스트 결과를 최종 보고서에 기록.
10. `git diff --cached`에 API 키·비공개 영상·개인정보·`.env`·`local-data`가 없는지 확인 후 `feature/swing3d`에 커밋 및 push. 변경 파일·테스트 수치·스크린샷 경로·커밋 해시·남은 제한을 보고.

**중간에 P0 또는 상담 UI까지만 끝내고 완료로 보고하지 마라. 전체 통합 MVP가 정상 작동해야 이번 작업이 완료다.** 현실적인 API 제한 때문에 차단되면 전체 구현 가능한 부분은 최대한 완성하고, 어떤 기능이 미검증인지 명확히 구분해 보고한다.
