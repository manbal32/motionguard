## 한 줄 요약

**껍데기는 거의 다 됐고, 제품의 핵심인 과장은 아직 화면에 나오지 않는다.**
원인은 렌더링이 아니라 그 아래 계측이다. 몸통·골반 채널이 대부분의 프레임에서 `0.0°` 로
나오고, 측정이 0 이면 과장 공식이 값을 그대로 돌려보낸다.

---

## 동작하는 것

실행해서 확인했다.

- **상담** — Gemini 다중 턴. 외부 전송 동의 체크박스, PC Enter 전송, 한글 조합 보호,
  모바일 버튼. 키가 없으면 **데모 모드라고 화면에 표시**하고 진행한다.
- **요약 승인** — `고민 / 개선하고 싶은 부분 / 사용자가 추정한 원인 / 연습 목표`
  네 칸이 수정 가능하고, 승인한 값이 종합 분석으로 넘어간다.
- **계측 파이프라인** — MediaPipe 33점 추출, 9채널 각도, 5국면 검출, 인물 크롭,
  국면 스틸컷, 트랙 캐시. 영상 하나가 끝까지 처리된다.
- **2D 비교 화면** — 왼쪽 원본 + 측정 관절, 오른쪽 에메랄드 사람형 아바타(클럽 포함).
  재생 · 구간 반복 · 0.5배속 · 프레임 이동 · 배율 슬라이더.
- **결과물** — 판정 목록, YouTube 검색 링크, 리포트 화면, 브라우저 인쇄 → PDF, 보조 3D.
- **자동 테스트** — Python 18개 + 서브테스트 8개 통과. JS 테스트 통과.

**과장 메커니즘 자체는 작동한다.** 사용자 실사용 영상의 스윙각 채널에서
`측정 87.4° → 과장 표시 110.9°` (2.5×) 가 확인됐다. 측정값이 0 이 아니면 걸린다.

`samples/golf_swing.mp4` (뒤·측면 촬영, 어드레스 어깨폭 30.3%)

| 국면 | 어깨폭(최대 대비) | 어드레스 기준 | 출력값 |
|---|---|---|---|
| 어드레스 | 30.3% | — | 0.00° |

이 영상은 **임팩트에서 몸이 카메라에 가장 정면**이다. 코드는 어드레스를 정면으로
가정하므로 그 이후가 전부 음수가 되고, 클램프가 0 으로 깎는다.

### 2. 피니시에서 부호가 되돌아온다

사용자 정면 영상(개인 자료, 저장소에 없음, 어드레스 어깨폭 96.8%)

| 국면 | 몸통 | 골반 | 교본(몸통) |
|---|---|---|---|
| 백스윙 탑 | +41.60° | +26.13° | +44° |
| 다운스윙 | +44.69° | +30.77° | +18° |
| 임팩트 | −63.03° | −40.68° | −28° |
| 피니시 | **+61.48°** | **+50.02°** | **−65°** |

부호를 손 위치에서 가져오는데, 손은 피니시에서 다시 올라온다.

### 3. 국면 검출이 실제 영상에서 깨진다

| 샘플 | 어드레스 | 탑 | 다운 | 임팩트 | 피니시 |
|---|---|---|---|---|---|
| `golf_swing.mp4` | 27 | 44 | **163** | **164** | 183 |
| 사용자 영상 | 164 | **171** | **171** | 174 | 215 |

다운스윙과 임팩트가 1프레임 차이, 사용자 영상은 탑과 다운스윙이 **같은 프레임**이다.
어드레스에서 탑까지 7프레임(60fps 기준 0.1초) — 실제 백스윙은 0.7초 이상이다.

### 4. 신뢰도가 전부 아니면 전무

| 샘플 | 신뢰도 0 인 표본 |
|---|---|
| `golf1_export.csv` | 84 / 108 (78%) |
| 사용자 정면 영상 | 87 / 137 (64%) |

필요한 16개 관절이 **모두** 보여야 신뢰도가 선다. 모션 블러에 전부 0 이 된다.
그 결과가 리포트의 `추적 신뢰도 0% · 낮음` 다섯 줄이다.

### 5. 접촉 시트 10컷 전부 과장 0

`mockups/shots/contact_04.png` — 국면 5개 × 배율 {1.0, 2.5} 전부 `과장 표시 0.0°`.
1.0배와 2.5배의 그림이 구별되지 않는다. 1번이 원인이다.

### 6. 관절 오버레이가 세로 영상에서 어긋난다

사용자 세로 영상에서 어깨선이 실제보다 위에 뜨고 다리 선이 길게 그려진다.
좌표 → 화면 변환이 가로 영상을 가정한다.

### 7. 세로 영상에서 비교와 수치가 한 화면에 안 들어온다

세로 영상이 패널을 꽉 채워 숫자를 보려면 스크롤해야 한다.
비교 화면의 요점은 둘을 동시에 보는 것이다.

### 8. 리포트가 고객용이 아니다

`mockups/shots/mvp_desktop_report.png` 기준.

- 1페이지에 9칸 각도 표가 나온다. 고객이 물어본 증상에 대한 답은 없다
- `추적 신뢰도 0%` 가 다섯 번 반복된다 (내부 지표)
- `어드레스 · 몸통 0.0° / 교본 0.0°` 처럼 차이가 0 인 항목을 피드백으로 나열한다
- `자기보고의 원인을 영상에서 확정할 수 없습니다` 가 자기진단에 대한 답의 전부다

→ 요구사항은 `MVP_INTEGRATION.md` 0-B 에 적혀 있다.

## 지금 진행 중인 작업

**`CODEX_RUN_05.md`** — 위 1~7 번을 고친다. 아직 시작되지 않았다.

순서: 결함 5(국면 검출) → 1(클램프) → 2(기준점) → 3(부호) → 4(신뢰도) → 6(오버레이) → 7(레이아웃)

**국면 검출이 가장 먼저다.** 국면이 틀리면 나머지 측정이 엉뚱한 프레임에서 나와
고쳐도 확인할 수 없다.

통과 조건 12개가 전부 숫자로 적혀 있다. 핵심 다섯 개:

| 항목 | 현재 | 통과 |
|---|---|---|
| 국면 간격 | 탑·다운 같은 프레임 | 어드레스→탑 0.30초↑, 탑→임팩트 0.15초↑ |
| 골반 (정면 샘플) | 탑·다운 0.0° | 0 이 아닐 것 |
| 피니시 부호 | +61.48° | 음수 |
| 측면 샘플 | 전부 0.0° | **"측정 불가"** (0 을 내지 않는다) |
| 신뢰도 0 비율 | 78% | 40% 미만 |

그 다음 라운드는 `MVP_INTEGRATION.md` 0-B(고객 언어 리포트)와 0-C(촬영 각도별 판정)다.
